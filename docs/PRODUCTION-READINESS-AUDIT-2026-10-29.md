# ممیزی جامع آمادگی بهره‌برداری پشکان — ۲۰۲۶-۱۰-۲۹

## نتیجه اجرایی

این ممیزی کد و مستندات را روی شاخه کاری ممیزی کرده و دو ریسک عملیاتی را اصلاح می‌کند: ارسال دوباره درخواست پس از timeout/refresh، و پذیرش هم‌زمان دو انتساب خودکار برای یک پرونده. قراردادهای پاسخ ملی پیامک و نگهداری کلید retry نیز مستند/سخت‌سازی شده‌اند. **نتیجه این سند مجوز اعلام آمادگی تولید نیست**: PostgreSQL واقعی، درگاه بانکی، پیامک زنده، مرورگر واقعی، استقرار و بازیابی خارج‌سرور در این دور اجرا نشده‌اند؛ چند قابلیت خواسته‌شده هم در مخزن موجود نیست یا فقط بخشی از آن پیاده شده است.

## معماری واقعیِ مشاهده‌شده

مخزن monorepo دو workspace دارد: `apps/api` (Express 5/TypeScript) و `apps/web` (React 19/Vite 7/Tailwind 4). مسیر معمول درخواست، middleware امنیت/نشست ← route و مجوز/اعتبارسنجی ← منطق دامنه `modules` ← لایه SQL/مهاجرت است. رابط وب برای همه نقش‌ها از REST API مشترک استفاده می‌کند؛ تنظیم وب از URL نسبی استفاده می‌کند. تولید برای PostgreSQL طراحی شده، اما آزمون‌ها و آزمون مهاجرت این دور با SQLite داخلی Node اجرا شدند. ۱۵ migration اکنون در شاخه کاری وجود دارد. PWA پیکربندی شده؛ این به‌تنهایی ساخت APK یا تأیید دستگاه Android نیست.

## تغییرات عملی این ممیزی

1. **جلوگیری از ثبت تکراری:** هدر اختیاری `Idempotency-Key` برای `POST /api/requests`، migration شماره ۱۵، HMAC محتوای مؤثر درخواست با کلید سرور، و بازگرداندن همان پرونده/فاکتور در retry یکسان اضافه شد. استفاده دوباره از کلید با payload متفاوت 409 می‌دهد. هدر در CORS مجاز شد. UI فقط کلید تصادفی عملیات را در `sessionStorage` می‌نویسد؛ داده فرم و fingerprint ذخیره نمی‌شوند. خطای 409 ناشی از استفاده مجدد کلید با داده متفاوت، کلید قدیمی را پاک می‌کند تا کاربر پس از بازبینی دوباره ارسال کند. مشتریان/کلاینت‌های قدیمی بدون هدر همان رفتار پیشین را دارند.
2. **انتساب خودکار:** ثبت پرونده با `UPDATE` شرطی (`assigned_to IS NULL` و وضعیت خوانده‌شده) در تراکنش حفاظت شد؛ اگر درخواست دیگری قبلاً آن را تخصیص داده یا تغییر وضعیت داده باشد، event تکراری ساخته نمی‌شود.
3. **ملی پیامک:** parser پاسخ رسمی متنی/عددی `RecId` و کدهای خطا را می‌پذیرد و قالب JSON قدیمی `RetStatus`/`Value` را برای سازگاری حفظ می‌کند. تست‌ها فقط پاسخ mock هستند.
4. **مستندات:** شرح قرارداد API، migrationها و MeliPayamak به‌روز شد. README به migration 015 اشاره می‌کند.
5. **مهاجرت تمیز:** SQLite موقت و خالی ایجاد شد؛ اجرای اول ۱۵ migration را اعمال کرد و اجرای دوم `applied=0 skipped=15` داد. migration 015 و جدول idempotency در همان پایگاه‌داده آزمایشی دیده شدند. هیچ داده مشتری/تولید استفاده نشد.

فایل‌های اصلی: `apps/api/src/modules/requests/service.ts`, `apps/api/src/routes/requests.ts`, `apps/api/src/http/app.ts`, `apps/api/src/modules/sms/provider.ts`, `apps/web/src/lib/api.ts`, `apps/web/src/pages/public/Services.tsx`, `apps/api/migrations/015_request_submission_idempotency.sql`, تست‌های `requests`, `sms-provider`, `http-security`, `migrations`, و `docs/API.md`, `docs/MELIPAYAMAK.md`, `docs/ARCHITECTURE.md`, `README.md`.

## شواهد آزمون اجراشده

تمام فرمان‌های زیر پس از تغییرات نهایی این دور اجرا شدند و زنجیره کامل با exit code صفر پایان یافت:

| فرمان | نتیجه مشاهده‌شده |
| --- | --- |
| `npm run typecheck` | API و وب موفق |
| `npm test` | API: ۱۸ فایل، ۱۰۰ تست؛ وب: ۲ فایل، ۱۷ تست، همگی موفق |
| `npm exec --workspace apps/api -- vitest run --config audit.config.ts` | ۱ فایل، ۱۶ تست پذیرش، همگی موفق |
| `npm run build` | build TypeScript API و Vite/PWA وب موفق؛ Workbox ساخت شد |
| `npm audit --audit-level=moderate` | exit code صفر؛ ۴ هشدار Low در `deepmerge` از زنجیره `@rollup/plugin-node-resolve → workbox-build → vite-plugin-pwa` باقی است. راه‌حل پیشنهادی `--force` نسخه breaking از `vite-plugin-pwa` نصب می‌کند و اجرا نشد. |
| `bash -n scripts/install.sh scripts/pishkan scripts/lib/common.sh` | موفق؛ پایان زنجیره کامل شد |
| مهاجرت SQLite موقت دوبار | بار اول ۱۵ اعمال، بار دوم صفر اعمال/۱۵ ردشده به‌عنوان قبلاً اعمال‌شده |

آزمون‌های کلیدی جدید: درخواست هم‌زمان با همان کلید فقط یک پرونده/فاکتور می‌سازد؛ کلید با داده متفاوت 409 می‌دهد؛ دو فراخوانی `autoAssign` روی یک پرونده فقط یک تخصیص و یک event ایجاد می‌کنند؛ دو کارمند واجد شرایط که هم‌زمان پرونده صف را claim می‌کنند، یک پاسخ موفق و یک 409 می‌گیرند و فقط یک event ساخته می‌شود؛ preflight CORS هدر idempotency را می‌پذیرد؛ پاسخ SMS متنی و JSON قدیمی با mock بررسی می‌شوند. تست‌های SQLite برای هم‌زمانی PostgreSQL جایگزین نیستند.

## منابع رسمی و بررسی مهارت UI/UX

- منابع رسمی MeliPayamak که در `docs/MELIPAYAMAK.md` ثبت شده‌اند: <https://www.melipayamak.com/api/>، `sendbybasenumber`, `sendbybasenumber2`, `sendsimplesms2`, `getcredit`, `sendotp` و مستند کنسول. معنی RecId متنی بلند/ReturnValue و پاسخ JSON اعتبار از هم تفکیک شده‌اند. خواندن مستند رسمی، تماس واقعی با سرویس‌دهنده نیست.
- مستند رسمی درگاه Zarinpal مرور شد: <https://www.zarinpal.com/docs/paymentGateway/> و <https://www.zarinpal.com/docs/paymentGateway/connectToGateway.html>. قرارداد Request/Verify و callback بررسی شد؛ هیچ‌کدام با حساب واقعی آزمایش نشدند.
- مهارت پیشنهادی UI/UX Pro Max از مخزن رسمی و بسته `ui-ux-pro-max-cli@2.15.0` بررسی ایمنی محدود شد؛ نسخه/integrity بسته npm با registry هم‌خوان بود و license MIT بود. همه فایل‌های وابستگی ممیزی کامل امنیتی نشدند. نصب/اجرای setup انجام نشد، چون CLI گزینه `--dry-run` ندارد و setup می‌تواند npm/Playwright دانلود کند؛ مخزن نام Arena را صریحاً در فهرست agentها ذکر نمی‌کند. بنابراین از آن به‌عنوان مهارت نصب‌شده یا منبع طراحی استفاده نشد.

## دروازه‌های باقی‌مانده پیش از انتشار عملیاتی

1. بازبینی/merge PRها با ترتیب درست (PR تغییرات این شاخه به شاخه PR شماره ۱، سپس PR شماره ۱ به `main`)؛ هیچ merge خودکاری انجام نشود.
2. اجرای تست migration، درخواست‌های تکراری/هم‌زمان، انتساب و ledger روی PostgreSQL واقعی و نسخه پشتیبان قبل از هر migration تولید.
3. مرورگر واقعی Chromium و موبایل RTL: refresh/timeout/409، upload و download خصوصی، keyboard/screen-reader، PWA cache/offline و CORS با origin واقعی.
4. حساب آزمایشی مالک برای SMS/درگاه، تأیید صریح شماره مقصد/مبلغ و آزمون sandbox/live تفکیک‌شده؛ بدون این‌ها هیچ «اتصال سالم» اعلام نشود.
5. ورود تعرفه/شرایط رسمیِ راستی‌آزمایی‌شده و تکمیل featureهای خارج از موجودی فعلی از جمله کوپن، CMS بنر/FAQ و retention/schedule مناسب.
6. نصب/ارتقا/rollback/restore PostgreSQL و فایل‌ها در میزبان جدا، نگهداری off-site، بازیابی کلید رمزنگاری و مانیتورینگ/هشدار واقعی.
7. رفع هشدار low وابستگی بدون downgrade شکستن PWA، یا ثبت پذیرش ریسک مشخص پس از بررسی maintainerها.

## بازاجرای آزمون‌های محلی

از ریشه مخزن و Node.js 22.22.2+:

```bash
npm ci
npm run typecheck
npm test
npm exec --workspace apps/api -- vitest run --config audit.config.ts
npm run build
npm audit --audit-level=moderate
bash -n scripts/install.sh scripts/pishkan scripts/lib/common.sh
```

این فرمان‌ها جای secretهای تولید، دسترسی سرویس‌های بیرونی، پایگاه‌داده PostgreSQL یا موافقت برای استقرار را نمی‌گیرند.
