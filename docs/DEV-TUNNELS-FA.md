# لینک عمومی برای نمایش (Microsoft Dev Tunnels)

این سند کاربرد، محدودیت‌ها و روش عیب‌یابی «انتشار روی اینترنت برای نمایش» را توضیح می‌دهد؛ همان گزینه‌ای که در نصب‌کنندهٔ ویندوز و در Pishkan Manager دیده می‌شود.

> **این قابلیت برای نمایش و آزمایش است، نه بهره‌برداری رسمی.** مایکروسافت برای Dev Tunnels تعهد سطح سرویس (SLA) نمی‌دهد، سقف مصرف ماهانه دارد و ممکن است رفتارش تغییر کند. برای استفادهٔ واقعی، دامنه و سرور اختصاصی خودتان را بگذارید.

---

## چه کاری می‌کند

سامانهٔ Pishkan روی ویندوز دفتر نصب می‌شود و فقط از شبکهٔ محلی (LAN) در دسترس است. با روشن‌کردن این گزینه، یک **آدرس اینترنتی امن** ساخته می‌شود که کارفرما از هر جایی — اینترنت موبایل، شهر دیگر — می‌تواند آن را باز کند و به همان سامانهٔ روی رایانهٔ شما وصل شود.

نکات مهم:

- **آدرس شبکهٔ محلی از کار نمی‌افتد.** هر دو آدرس هم‌زمان کار می‌کنند: آدرس `192.168.x.x` برای گوشی‌های همان Wi‑Fi، و آدرس عمومی برای بیرون از شبکه.
- **هیچ پورتی روی مودم باز نمی‌شود و IP عمومی لازم نیست.** ابزار مایکروسافت از داخل به بیرون وصل می‌شود؛ بنابراین پشت NAT و بدون تنظیم مودم کار می‌کند.
- **ورود به سامانه دست‌نخورده است.** نام کاربری و رمز عبور Pishkan همچنان لازم است. لینک عمومی فقط «راه رسیدن» است، نه «اجازهٔ ورود».
- **کل سیستم در دسترس است**: صفحهٔ سایت، پنل مدیر، API و فایل‌های آپلودی، همه از یک پورت و یک لینک.

---

## چطور روشن می‌شود

### در نصب‌کننده

در صفحهٔ تنظیمات نصب، تیک **«انتشار روی اینترنت برای نمایش»** را بزنید (زیر گزینهٔ دسترسی LAN). نصب‌کننده به‌ترتیب این کارها را انجام می‌دهد:

1. **مرحلهٔ ۴ — دانلود ابزار:** فایل `devtunnel.exe` را دانلود و بررسی می‌کند. اگر یکی از منابع در دسترس نباشد، منبع بعدی را امتحان می‌کند (پایین را ببینید).
2. بقیهٔ نصب به‌طور عادی انجام می‌شود.
3. **مرحلهٔ ۱۱ — ورود و لینک:** یک پنجرهٔ مرورگر برای ورود باز می‌شود. با حساب مایکروسافت، Entra ID (حساب سازمانی) یا GitHub وارد شوید. بعد از ورود، ابزار بقیهٔ تنظیمات را خودش انجام می‌دهد و در پایان نصب، **لینک عمومی روی صفحهٔ پایانی نمایش داده می‌شود**.
4. سرویس یک بار به‌طور خودکار دوباره راه‌اندازی می‌شود تا تنظیمات امنیتی جدید (کوکی HTTPS و مبدأ مجاز) اعمال شود.

### در Pishkan Manager (بعد از نصب)

دکمهٔ **«لینک عمومی / تونل»** در نوار بالای پنجره. در پنجرهٔ بازشده:

- اگر خاموش است: **«فعال‌سازی لینک عمومی»** را بزنید. اگر ابزار نصب نباشد، همان‌جا دانلود می‌شود؛ اگر وارد نشده باشید، صفحهٔ ورود باز می‌شود.
- اگر روشن است: لینک و **QR** نمایش داده می‌شود، و دکمهٔ **«خاموش کردن لینک عمومی»** آن را می‌بندد.
- لینک ساخته‌شده **خودکار در حافظه کپی** می‌شود تا بتوانید مستقیم برای کارفرما بفرستید.

### در برنامهٔ اندروید

هیچ تغییری لازم نیست. در صفحهٔ **«آدرس سامانه»** همان لینک عمومی را وارد کنید (مثلاً `https://pishkan-xxxxxxxx-3000.usw2.devtunnels.ms`). QR را هم می‌توانید با دوربین گوشی بخوانید.

## منابع دانلود و جایگزین‌ها

ابزار از چند مسیر مستقل تهیه می‌شود، چون `aka.ms` در بعضی شبکه‌ها در ایران مسدود است:

| ترتیب | منبع | توضیح |
|---|---|---|
| ۱ | `aka.ms/TunnelsCliDownload/win-x64` | لینک رسمی و همیشه آخرین نسخه |
| ۲ | `winget install Microsoft.devtunnel` | مسیر و CDN متفاوت؛ وقتی مسیر اول بسته باشد معمولاً کار می‌کند |
| ۳ | فایل دستی | اگر هر دو ناموفق بودند (پایین را ببینید) |

هر فایل دانلودشده **قبل از استفاده بررسی می‌شود**: باید فایل اجرایی ویندوز باشد (نه صفحهٔ HTML خطا)، اندازهٔ معقول داشته باشد و `--version` را با موفقیت برگرداند. اگر یکی از این‌ها نباشد، همان فایل دور ریخته می‌شود و منبع بعدی امتحان می‌شود — هرگز «نصب شد» اعلام نمی‌شود مگر ابزار واقعاً اجرا شود.

### نصب دستی (وقتی همهٔ منابع بسته‌اند)

1. روی یک رایانهٔ دیگر (یا با شبکهٔ دیگر) فایل را از `https://aka.ms/TunnelsCliDownload/win-x64` بگیرید.
2. نام آن را به `devtunnel.exe.download` تغییر دهید.
3. آن را در پوشهٔ `windows\bin` داخل پوشهٔ نصب Pishkan بگذارید.
4. نصب را دوباره اجرا کنید، یا در Manager دکمهٔ «فعال‌سازی لینک عمومی» را بزنید. فایل بررسی و جای‌گذاری می‌شود.

## خطاهای رایج

| نشانه | علت | کار |
|---|---|---|
| «هر سه مسیر امتحان شد» | شبکه دسترسی به مایکروسافت را می‌بندد | نصب دستی بالا؛ یا فعلاً این گزینه را خاموش بگذارید |
| «ورود تکمیل نشد» | پنجرهٔ مرورگر بسته شد یا ورود لغو شد | دوباره از Manager تلاش کنید |
| لینک باز می‌شود ولی ورود کار نمی‌کند | سرویس با تنظیمات قدیمی اجرا شده | در Manager «راه‌اندازی دوباره» را بزنید |
| «صفحهٔ هشدار مایکروسافت» در مرورگر | صفحهٔ ضدفیشینگ فقط بار اول | یک بار تأیید/ادامه بدهید؛ برای برنامهٔ اندروید نمایش داده نمی‌شود |
| لینک بعد از چند هفته از کار افتاد | تونل بی‌استفاده پس از ۳۰ روز حذف می‌شود | در Manager دوباره فعال کنید؛ تونل خودکار ساخته می‌شود |

لاگ ابزار در `.data/logs/devtunnel.log` و وضعیت آن در `.data/devtunnel.json` است. **هیچ رمز یا توکنی در این فایل‌ها ذخیره نمی‌شود**؛ توکن ورود در مخزن اعتبارنامهٔ ویندوز می‌ماند.

## محدودیت‌های سرویس

| مورد | سقف |
|---|---|
| ترافیک | ۵ گیگابایت در ماه برای هر کاربر |
| تعداد تونل | ۱۰ |
| تعداد پورت در هر تونل | ۱۰ |
| اتصال هم‌زمان | ۱٬۰۰۰ در هر پورت |
| درخواست | ۱٬۵۰۰ در دقیقه در هر پورت |
| سرعت | ۲۰ مگابایت بر ثانیه |
| حجم هر درخواست | ۱۶ مگابایت |
| زمان انتظار HTTP | حدود ۶۰ ثانیه |
| ماندگاری تونل بی‌استفاده | ۳۰ روز (سپس حذف) |
| وضعیت سرویس | Public Preview بدون SLA |

برای نمایش و تست، این سقف‌ها کافی است. برای بار واقعی کارفرما (آپلودهای بزرگ، هم‌زمانی بالا، آپلود فایل بیش از ۱۶ مگابایت) مناسب نیست.

## چرا این معماری

**چرا تونل و نه باز کردن پورت روی مودم؟** باز کردن پورت به IP عمومی ثابت، تنظیم مودم و در بسیاری از شبکه‌های ایران امکان‌پذیر نیست. تونل از داخل به بیرون tunnel می‌زند و به هیچ تنظیمی روی مودم نیاز ندارد.

**چرا `create` + `host <id>` و نه `host -p <port>`؟** تونل موقت (`host -p`) با بستن پنجره حذف می‌شود و لینک می‌میرد. یک تونل ماندگار با شناسهٔ ثابت ساخته می‌شود تا:
- لینک بین اجراهای مختلف همان نصب **تغییر نکند**،
- Manager بتواند آن را خاموش/روشن کند،
- پس از ری‌استارت رایانه همان لینک برگردد.

شناسهٔ تونل از مسیر نصب مشتق می‌شود (`pishkan-<hash>`)، بنابراین نصب دوباره روی همان پوشه همان لینک را می‌دهد.

**چرا `--allow-anonymous`؟** کارفرما نمی‌تواند با حساب مایکروسافت شما وارد شود و برنامهٔ اندروید هم هدر `X-Tunnel-Authorization` نمی‌فرستد. دسترسی باز در سطح تونل است؛ **محافظت واقعی، صفحهٔ ورود خودِ Pishkan است**. اگر این را نمی‌خواهید، این گزینه را روشن نکنید.

**سه تنظیمی که با روشن‌شدن تونل عوض می‌شوند:**

| کلید | مقدار | چرا |
|---|---|---|
| `COOKIE_SECURE` | `true` | بدون آن مرورگر کوکی نشست را روی HTTPS نمی‌فرستد و ورود «بی‌اثر» می‌شود |
| `CORS_ORIGINS` | + آدرس تونل | محافظ مبدأ هر درخواست تغییردهنده را رد می‌کند؛ بدون آن فرم ورود از لینک عمومی رد می‌شود |
| `APP_URL` | آدرس تونل | تا لینک‌های مطلق (پیامک/اعلان) به آدرس محلی رایانه اشاره نکنند |

هنگام خاموش‌کردن، هر سه به حالت محلی برمی‌گردند و مبدأهای دلخواهِ اضافه‌شده دست‌نخورده می‌مانند.

## فایل‌های مرتبط

| فایل | نقش |
|---|---|
| `windows/lib/devtunnel.mjs` | توابع خالص: استخراج آدرس از خروجی، محاسبهٔ تنظیمات، نام تونل، خواندن/نوشتن وضعیت |
| `windows/lib/devtunnel-control.mjs` | اجرای واقعی CLI: دانلود، ورود، ساخت، host، خاموشی |
| `windows/lib/tunnel-download.ps1` | دانلود با چند منبع و بررسی فایل (قبل از نصب Node قابل اجراست) |
| `windows/lib/tunnel-integration.mjs` | آزمون سرتاسری با CLI تقلبی (`npm run test:windows:tunnel`) |
| `docs/DEV-TUNNELS-ROADMAP-FA.md` | پژوهش اولیه و گزینه‌هایی که بررسی و رد شدند |
