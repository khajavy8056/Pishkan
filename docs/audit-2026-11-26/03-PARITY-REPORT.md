# گزارش تطبیق ویندوز ↔ سرور — تک پیشخوان

تاریخ: ۲۰۲۶-۱۱-۲۶ · شاخه: `arena/fe627e67-pishkan` · نسخه: `1.0.1218`

## اصل معماری تضمین‌کنندهٔ تطبیق

ویندوز و سرور **یک کدبیس واحد** را اجرا می‌کنند: همان Express API، همان React وب،
همان ماژول‌های دامنه، همان RBAC، همان مهاجرت‌ها. تنها تفاوت‌ها:

| جنبه | ویندوز (لوکال) | سرور (تولید) |
| --- | --- | --- |
| دیتابیس | SQLite (`node:sqlite`) | PostgreSQL 15/16 |
| وب‌سرور | خود API (پورت لوکال) | nginx + API پشت proxy |
| TLS | ندارد (LAN اختیاری) | Let's Encrypt / Cloudflare Origin |
| نصب‌کننده | مدیر گرافیکی PowerShell | `install.sh` + CLI `pishkan` |
| پیامک/درگاه | console/غیرفعال تا تنظیم | همان سرویس‌ها با اعتبارنامهٔ واقعی |

چون منطق دامنه مشترک است، تطبیق با «اجرای یک سوئیت روی هر دو دیتابیس» تضمین می‌شود،
نه با دو پیاده‌سازی جدا. هر کوئری برای هر دو گویش نوشته شده است.

## شواهد اجرای واقعی

- **سوئیت API روی SQLite:** کامل سبز (نتیجهٔ نهایی در `05-TEST-REPORT.md`).
- **سوئیت API روی PostgreSQL 16 واقعی:** همان سوئیت، نتیجه در `04-DB-COMPATIBILITY.md`.
- **selftest کتابخانهٔ ویندوز:** `node windows/lib/selftest.mjs` → **۵۲/۵۲** موفق
  (۲ مورد skip: bind مدیر LAN نیازمند dist، و قانون واقعی فایروال ویندوز فقط روی Windows).
  این تست منطق نصب‌کننده/مدیر ویندوز (envfile، LAN، QR، tunnel، ps-lint، log sanitize) را
  روی همین محیط لینوکس اجرا می‌کند — لایهٔ PowerShell GUI روی ویندوز واقعی جداگانه تأیید می‌شود.
- **build وب + PWA و build API:** موفق؛ سرویس‌ورکر با ۱۱۹ precache تولید شد.

## واگرایی‌های شناسایی‌شده و رفع‌شده

1. **F4 (rowid):** تست push-stage-payload از `rowid` مخصوص SQLite استفاده می‌کرد ⇒ به
   `created_at` قابل‌حمل تغییر یافت؛ اکنون روی هر دو DB سبز است.
2. **F3 (pg_dump):** مسیر باینری در سرور قابل override شد (`PG_DUMP_BIN`/`PG_RESTORE_BIN`)
   تا عدم تطابق نسخهٔ client/server اوبونتو مدیریت شود.
3. **بازیابی SQLite در production ممنوع** (فقط توسعه/آزمون)؛ بازیابی PG فقط از CLI روی سرور
   با سرویس متوقف و تأیید صریح — این تفاوت عمدی و ایمن است، نه واگرایی نقص.

## مواردی که فقط روی محیط واقعی قابل تأیید نهایی‌اند (صادقانه)

- لایهٔ PowerShell GUI ویندوز و قانون واقعی Windows Defender Firewall (نیازمند Windows واقعی).
- اتصال دائمی HTTPS اندروید روی دستگاه واقعی (به‌درخواست کاربر به مرحلهٔ پس از نصب موکول شد).
- پیامک/درگاه زنده (نیازمند اعتبارنامهٔ واقعی).

نتیجه: **تطبیق منطق دامنه بین ویندوز و سرور با اجرای یک سوئیت روی هر دو دیتابیس تأیید شد؛**
هیچ واگرایی رفع‌نشدهٔ بحرانی باقی نمانده است.
