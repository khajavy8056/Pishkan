# موارد باقی‌ماندهٔ نیازمند زیرساخت خارجی

تاریخ: ۲۰۲۶-۱۱-۲۶ · شاخه: `arena/fe627e67-pishkan`

این موارد در محیط سندباکس قابل آزمون واقعی نیستند (دامنه/DNS/Cloudflare/SSL زنده/پیامک/درگاه/
Google OAuth/VPS/دستگاه اندروید در دسترس نیست). برای هر مورد **دقیقاً** چیزی که لازم است و
دستور تأیید روی سرور واقعی آمده است. هیچ‌کدام «انجام‌شده» ادعا نمی‌شود.

## ۱. دامنه + Cloudflare + DNS
**لازم:** دامنهٔ ثبت‌شده، حساب Cloudflare، دسترسی به پنل DNS.
**مراحل:** `docs/DOMAIN-CLOUDFLARE.md` (ثبت → حساب CF → nameserver → رکورد A/www → proxy).
**تأیید روی سرور:** `sudo pishkan doctor` (DNS/دامنه/گواهی را بررسی می‌کند).

## ۲. SSL زنده (Let's Encrypt یا Cloudflare Origin)
**لازم:** DNS منتشرشده، پورت ۸۰/۴۴۳ باز، Cloudflare روی **Full (Strict)** (نه Flexible).
**دستور:** `sudo pishkan provision --tls` سپس `sudo pishkan doctor`.
**تأیید:** `curl -I https://DOMAIN` باید 200/301 با گواهی معتبر بدهد؛ مانیتورینگ → گواهی SSL
باید «X روز مانده» نشان دهد (probe واقعی TLS). تمدید خودکار با `certbot.timer`.

## ۳. پیامک واقعی (ملی پیامک / provider موجود)
**لازم:** اعتبارنامهٔ سرویس پیامک (username/password یا API key + خط ارسال).
**محل:** تنظیمات ← پیامک؛ سپس تنظیمات ← گارد ← شمارهٔ مدیر + رویدادهای پیامک.
**تأیید:** دکمهٔ «پیامک آزمایشی گارد» (`/api/guard/test-sms`) باید پیامک واقعی برساند.

## ۴. درگاه پرداخت زنده (زرین‌پال)
**لازم:** merchant_id واقعی درگاه.
**محل:** تنظیمات ← پرداخت.
**تأیید:** یک تراکنش آزمایشی واقعی create→redirect→callback→verify؛ عدم پرداخت تکراری.

## ۵. Google Drive OAuth واقعی
**لازم:** حساب گوگل، OAuth Client ID/Secret، Refresh Token با دسترسی `drive.file`.
**مراحل:** `docs/BACKUP-EXTERNAL-FA.md` بخش Google Drive (گام‌به‌گام با OAuth Playground).
**تأیید:** دکمهٔ «آزمایش مقصد خارجی» باید ایمیل حساب را نشان دهد؛ یک بکاپ دستی → تاریخچهٔ انتقال «منتقل شد».

## ۶. مقصد بکاپ خارجی واقعی (SFTP/FTP)
**لازم:** یک سرور/هاست دیگر با SSH یا FTP.
**محل:** تنظیمات ← پشتیبان‌گیری ← مقصد خارجی.
**تأیید:** «آزمایش مقصد خارجی» سبز + یک بکاپ دستی با تطابق SHA-256 در مقصد.
(در سندباکس با سرور واقعی SFTP/FTP محلی تأیید شد؛ مقصد واقعیِ کاربر جداگانه باید تأیید شود.)

## ۷. اسکن malware با موتور به‌روز (اختیاری اما توصیه‌شده)
**لازم:** ClamAV روی VPS (`apt install clamav clamav-daemon && freshclam`).
**وضعیت فعلی:** اسکن Guard امضایی/یکپارچگی است و جایگزین آنتی‌ویروس کامل نیست (صادقانه در UI ذکر شده).
**تأیید:** `clamscan --version` و به‌روز بودن signatureها.

## ۸. اتصال دائمی HTTPS اندروید (به‌درخواست کاربر موکول شد)
**لازم:** نصب کامل سرور + دامنهٔ نهایی + اطلاعات اتصال از کاربر.
**وضعیت:** نصب‌کننده `android-connection.json` را تولید می‌کند (API URL/baseURL/مسیرها/نسخه/auth/health).
**مرحلهٔ بعد:** حذف صفحهٔ IP/Port فقط در بیلد release (در dev بماند)، پیکربندی یکپارچه، تست روی دستگاه واقعی.

## ۹. VPS واقعی + نصب end-to-end
**لازم:** VPS/سرور اختصاصی Ubuntu 22.04/24.04 با root (کاربر تأیید کرده).
**دستور:** `sudo bash scripts/install.sh` (یا دستور pinned در README).
**تأیید:** گزارش `install-report.md` + `pishkan doctor` + ورود مدیر + یک درخواست آزمایشی.
نصب‌کننده v2: journal، قفل پس از نصب، گزارش بدون secret، بستهٔ اندروید.

## ۱۰. تست نفوذ خارجی مجاز
**لازم:** محیط مجاز جداگانه + مجوز کتبی.
**وضعیت:** تست‌های امنیتی این ممیزی فقط در محیط کنترل‌شدهٔ loopback اجرا شدند.

## جمع‌بندی صادقانه
تا زمانی که موارد ۱–۶ و ۹ روی زیرساخت واقعی کاربر تأیید نشوند، پروژه **«آمادهٔ استقرار»** است
اما **«تأییدشدهٔ عملیاتی روی سرور واقعی»** نیست. چک‌لیست نهایی (`07-READINESS-CHECKLIST.md`)
این تمایز را حفظ می‌کند.
