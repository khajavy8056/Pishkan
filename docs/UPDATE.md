# به‌روزرسانی و بازگشت

## اصل حاکم

به‌روزرسانی هرگز نباید مشتری، پرونده، فاکتور، تراکنش، تنظیمات یا حساب مدیر را حذف کند.
پشکان با سه مکانیزم این را تضمین می‌کند:

1. **مهاجرت‌های نسخه‌بندی‌شده** (`apps/api/migrations/00N_*.sql`): فقط `CREATE TABLE IF NOT EXISTS`،
   `ALTER TABLE ... ADD COLUMN` و داده‌های اولیه. هیچ مهاجرتی `DROP` روی جدول داده ندارد.
   شماره مهاجرت‌های اجراشده در جدول `schema_migrations` نگه داشته می‌شود.
2. **انتشار نسخه‌ها در مسیرهای جدا** (`/opt/pishkan/releases/<timestamp>`) و فعال‌سازی با لینک نمادین اتمیک.
3. **بازگشت خودکار**: اگر سرویس جدید سالم بالا نیاید، نسخه قبلی فعال می‌شود.

## به‌روزرسانی استاندارد

```bash
sudo pishkan update
```

مراحل داخلی:

1. پشتیبان‌گیری خودکار (پایگاه داده + مدارک) در `/var/backups/pishkan`.
2. `git clone --depth 1` از شاخه `main` در مسیر نسخه جدید.
3. `npm ci` و ساخت API و وب؛ در صورت خطای ساخت، نسخه فعلی دست‌نخورده می‌ماند.
4. اجرای مهاجرت‌ها؛ در صورت خطا، نسخه جدید رها و نسخه فعلی حفظ می‌شود.
5. تغییر لینک `current`، بازنویسی سرویس systemd و راه‌اندازی مجدد.
6. بررسی `/api/health` تا ۹۰ ثانیه؛ در صورت شکست، بازگشت خودکار به نسخه قبلی.

### گزینه‌ها

```bash
sudo pishkan update --ref v1.2.0      # نصب یک تگ/شاخه مشخص
sudo pishkan update --no-backup       # فقط وقتی پشتیبان تازه دارید
```

## بازگشت به نسخه قبلی

```bash
sudo pishkan rollback                 # آخرین نسخه پیشین
sudo pishkan rollback --to 20260101120000
```

بازگشت، **کد** را برمی‌گرداند. اگر نسخه جدید مهاجرت داده انجام داده باشد:

- ستون‌های جدید باقی می‌مانند (بی‌ضرر برای کد قدیمی در بیشتر موارد).
- اگر مهاجرت رفتار داده را تغییر داده باشد، ممکن است بازیابی پایگاه داده لازم شود:
  ```bash
  sudo pishkan restore /var/backups/pishkan/pishkan-backup-<timestamp>.tar.gz
  ```
- همیشه پیش از بازگشت، پشتیبان فعلی را نگه دارید (`sudo pishkan backup`).

## رویه توصیه‌شده برای به‌روزرسانی روی سرور عملیاتی

1. اطلاع‌رسانی به کاربران در ساعات کم‌ترافیک.
2. `sudo pishkan backup` (علاوه بر پشتیبان خودکار به‌روزرسانی).
3. انتقال نسخه پشتیبان به مقصد خارج از سرور (`docs/BACKUP-RESTORE.md`).
4. `sudo pishkan update`.
5. بررسی سریع: ورود مدیر، باز شدن کاتالوگ، ثبت یک درخواست آزمایشی، مشاهده داشبورد.
6. در صورت مشاهده مشکل: `sudo pishkan rollback`.

## چرخه عمر نسخه‌ها

- نسخه‌های فعال و قبلی در `/opt/pishkan/releases` می‌مانند.
- برای پاک کردن نسخه‌های قدیمی (فقط پس از چند روز پایداری):
  ```bash
  ls -1dt /opt/pishkan/releases/*/ | tail -n +4 | xargs -r sudo rm -rf
  ```
  حداقل دو نسخه آخر را نگاه دارید تا `rollback` ممکن بماند.

## به‌روزرسانی دستی (بدون CI/CD)

```bash
cd /opt/pishkan/current
sudo -u pishkan git pull        # فقط اگر این مسیر خودش مخزن گیت باشد
sudo -u pishkan npm ci
sudo -u pishkan npm run build
sudo pishkan migrate
sudo systemctl restart pishkan-api
sudo pishkan health
```

توصیه: به‌جای این روش از `pishkan update` استفاده کنید تا امکان بازگشت خودکار حفظ شود.
