# اتصال پیامک (ملی پیامک)

پشکان برای پیامک از **ملی پیامک** به‌عنوان ارائه‌دهنده پیش‌فرض استفاده می‌کند، اما ارسال پیامک
از طریق یک لایه انتزاعی (`modules/sms/provider.ts`) انجام می‌شود تا در آینده ارائه‌دهنده دیگری
بدون تغییر منطق سامانه اضافه شود.

> **تاریخ بازبینی سند: ۲۰۲۶-۱۰-۲۴.** منابع بررسی‌شده:
> - مرور کلی وب‌سرویس: <https://www.melipayamak.com/api/>
> - ارسال کد یک‌بارمصرف و کدهای بازگشتی: <https://www.melipayamak.com/api/sendotp/>
> - احراز هویت با کلید API: <https://www.melipayamak.com/blog/posts/send-sms-by-api-key/>
> - کنسول و API توکنی: <https://www.melipayamak.com/blog/posts/melipayamak-console/>
> - راهنمای وب‌سرویس خطوط اشتراکی/الگو: <https://www.melipayamak.com/help/sharedwebserviceguide/>
>
> **در این محیط، ارسال واقعی پیامک انجام نشده است** (دسترسی شبکه به سرویس‌دهنده و اعتبارنامه وجود ندارد).
> آنچه آزمون شده، فقط مسیر کد و رفتار خطا با پاسخ شبیه‌سازی‌شده است. پیش از اتکا، با حساب واقعی
> «بررسی اتصال» و «ارسال پیامک آزمایشی» را در پنل مدیریت اجرا کنید.

## ۱. چه چیزی در سامانه پیاده‌سازی شده است؟

| حالت (`sms.auth_mode`) | مسیر فراخوانی | کاربرد |
| --- | --- | --- |
| `credentials` (پیش‌فرض) | `POST https://rest.payamak-panel.com/api/SendSMS/BaseServiceNumber` با `username`, `password`, `text`, `to`, `bodyId` | ارسال کد تأیید با **الگوی تأییدشده** |
| `credentials` (پیام ساده) | `POST .../api/SendSMS/SendSMS` با `username`, `password`, `to`, `from`, `text`, `isFlash` | پیام اطلاع‌رسانی از خط اختصاصی |
| `apikey` | همان مسیرها، اما به‌جای رمز از **کلید API** پنل استفاده می‌شود | امن‌تر؛ رمز پنل لازم نیست |
| `console` | `POST https://console.melipayamak.com/api/send/shared/{token}` با `{bodyId, to, args}` | کنسول جدید با توکن در مسیر URL |
| `console` (پیام ساده) | `POST https://console.melipayamak.com/api/send/simple/{token}` | — |
| `provider=console` | بدون ارسال واقعی؛ فقط لاگ سرور | محیط توسعه |

نکات پیاده‌سازی:

- `sms.base_url` قابل تغییر از پنل است؛ اگر ملی پیامک مسیر را تغییر داد، بدون انتشار نسخه جدید می‌توان اصلاح کرد.
- توکن در حالت کنسول بخشی از مسیر URL است، بنابراین **هرگز لاگ نمی‌شود** (لاگ‌ها فقط مقصد ماسک‌شده و متن پیام را دارند).
- شماره موبایل قبل از ارسال نرمال می‌شود (`+98…`, `0098…`, `98…`, `9xxxxxxxxx` → `09xxxxxxxxx`).
- ارقام فارسی/عربی در نام کاربری، کلید و `bodyId` به لاتین تبدیل می‌شوند.
- پاسخ‌های خطا به پیام فارسی قابل‌فهم ترجمه می‌شوند و در «لاگ پیامک» پنل مدیریت قابل مشاهده‌اند.

### کدهای بازگشتی

سامانه پاسخ موفق را با `RetStatus = 1` و مقدار `Value` مثبت تشخیص می‌دهد و برای خطاها این نقشه را دارد:

| کد | معنا |
| --- | --- |
| 0 | نام کاربری یا رمز/کلید اشتباه |
| 1 | درخواست نامعتبر |
| 2 | اعتبار حساب کافی نیست |
| 3 | محدودیت ارسال روزانه |
| 4 | محدودیت حجم ارسال |
| 5 | شماره فرستنده نامعتبر |
| 6 | سرویس در حال به‌روزرسانی |
| 7 | متن شامل کلمه فیلترشده |
| 9 | ارسال از خطوط عمومی با وب‌سرویس مجاز نیست |
| 10 | گیرنده در لیست سیاه مخابرات |
| 108 | IP سرور مجاز نیست |
| 109 | استفاده از کلید API الزامی است |
| 110 | دسترسی وب‌سرویس فعال نیست |
| 111 | IP درخواست‌کننده نامعتبر |

> **هشدار تطبیق:** در برخی نسخه‌های مستندات، کدهای خطا با علامت منفی (`-2`, `-108` …) فهرست شده‌اند.
> پیاده‌سازی فعلی هر دو شکل را با نرمال‌سازی مقایسه می‌کند، اما **پیش از اتکا در محیط عملیاتی،
> با یک حساب آزمایشی کدهای واقعی را تأیید کنید** و در صورت تفاوت، نقشه `PANEL_CODES` در
> `apps/api/src/modules/sms/provider.ts` را اصلاح کنید.

## ۲. راه‌اندازی گام‌به‌گام

### الف) پیش‌نیازهای حساب ملی پیامک

1. حساب سازمانی/حقوقی در ملی پیامک با **خط اختصاصی** (برای ارسال اطلاع‌رسانی) یا امکان استفاده از **الگو**.
2. یک **الگوی تأییدشده** (Body ID) برای کد ورود. مثال متن الگو:
   `کد ورود شما به سامانه دفتر پیشخوان: {0}`
   متغیر `{0}` در ارسال با `args` پر می‌شود.
3. فعال‌سازی وب‌سرویس در پنل: **تنظیمات → وب‌سرویس** و ثبت IP سرور شما (در صورت محدودیت IP).
   - در صورت استفاده از حالت `apikey`، کلید API را از همان بخش بردارید.

### ب) وارد کردن تنظیمات در سامانه

**تنظیمات سامانه → پیامک و ملی پیامک**:

| کلید تنظیمات | مقدار نمونه | توضیح |
| --- | --- | --- |
| `sms.provider` | `melipayamak` | ارائه‌دهنده |
| `sms.enabled` | روشن | اگر خاموش باشد هیچ پیامکی ارسال نمی‌شود و کد ورود در محیط توسعه در پاسخ API برمی‌گردد |
| `sms.auth_mode` | `credentials` یا `apikey` یا `console` | روش احراز |
| `sms.username` | `۹۸۹۱۲…` یا `username` | نام کاربری پنل (ارقام فارسی هم پذیرفته می‌شود) |
| `sms.password` | ••••••• | رمز پنل یا کلید API (رمزنگاری‌شده ذخیره می‌شود) |
| `sms.api_key` | ••••••• | کلید API (در حالت `apikey`/`console`) |
| `sms.sender_line` | `+983000xxxx` | شماره خط فرستنده (برای پیام ساده) |
| `sms.otp_template_id` | `123456` | شناسه الگوی تأییدشده کد ورود (`bodyId`) |
| `sms.otp_template_body` | `کد ورود شما: {0}` | متن الگو (برای مستندسازی و پیامک ساده) |
| `sms.otp_param_name` | `{0}` | نام متغیر در الگو |
| `sms.base_url` | `https://rest.payamak-panel.com/api` | آدرس وب‌سرویس |
| `sms.daily_limit` | `500` | سقف ارسال روزانه سامانه (محافظ در برابر سوءاستفاده) |
| `sms.log_body` | خاموش | ذخیره متن پیام در لاگ (برای حریم خصوصی، خاموش نگه دارید) |
| `sms.test_recipient` | شماره خودتان | مقصد پیش‌فرض آزمون |

**مقادیر حساس هرگز به مرورگر ارسال نمی‌شوند.** در فرم تنظیمات فقط «مقدار ذخیره شده: `••••1234`» نمایش داده
می‌شود و برای تغییر باید مقدار جدید وارد کنید.

### ج) آزمون

1. دکمه **«بررسی اتصال»** → در حالت `credentials` با `GetCredit` اعتبار حساب را می‌خواند و
   در حالت `console` فقط وجود توکن را تأیید می‌کند (ارسال واقعی، تنها راه آزمون کامل است).
2. شماره مقصد خود را وارد کنید و **«ارسال پیامک آزمایشی»** را بزنید. سامانه بدون شماره مشخص ارسال نمی‌کند
   و برای هر ارسال تأیید می‌گیرد.
3. نتیجه در **لاگ پیامک** (همان صفحه) و در `sms_logs` پایگاه داده ثبت می‌شود:
   وضعیت `sent`/`failed`، کد خطا و شناسه پیام سرویس‌دهنده.
4. سپس یک بار «فراموشی رمز» یا ورود با کد پیامکی را با شماره واقعی کامل آزمون کنید
   (کد باید در ۲ دقیقه برسد و پس از ۵ تلاش ناموفق باطل شود).

## ۳. سیاست ارسال و محدودیت‌ها

- کد ورود: طول پیش‌فرض ۵ رقم، اعتبار ۱۲۰ ثانیه، حداکثر ۵ تلاش، فاصله ارسال مجدد ۶۰ ثانیه،
  سقف روزانه بر اساس `sms.daily_limit`.
- پیامک فقط برای رویدادهای تعریف‌شده ارسال می‌شود (کد ورود، اطلاع‌رسانی تغییر وضعیت در صورت فعال بودن).
- در محیط توسعه (`NODE_ENV != production`) و وقتی `sms.provider=console` یا `sms.enabled=false` باشد،
  کد در پاسخ API با فیلد `debugCode` برگردانده می‌شود تا آزمون محلی ممکن باشد. **این رفتار در تولید غیرفعال است.**
- متن پیامک باید با الگوی تأییدشده مطابق باشد؛ ارسال متن آزاد از خطوط عمومی توسط اپراتور محدود می‌شود.

## ۴. عیب‌یابی

| پیام | علت محتمل | اقدام |
| --- | --- | --- |
| «نام کاربری یا رمز عبور اشتباه است» | اشتباه در رمز/کلید یا استفاده از رمز به‌جای کلید API | کلید API را در حالت `apikey` وارد کنید |
| «IP سرور مجاز نشده است» (108) | IP سرور در پنل ملی پیامک ثبت نشده | IP عمومی خروجی سرور را ثبت کنید (`curl -s ifconfig.me`) |
| «ارسال از خطوط عمومی مجاز نیست» (9) | استفاده از وب‌سرویس برای خط عمومی | از الگوی تأییدشده (`bodyId`) استفاده کنید |
| «متن شامل کلمه فیلترشده است» (7) | متن پیام | متن را اصلاح کنید یا الگو را دوباره ثبت کنید |
| «اعتبار کافی نیست» (2) | شارژ حساب | شارژ کنید |
| کد می‌رسد ولی وارد نمی‌شود | اختلاف زمان سرور یا مصرف‌شدن کد | `timedatectl` را بررسی و ساعت را با NTP همگام کنید |
| «ارتباط برقرار نشد» | فایروال خروجی یا DNS | `curl -sI https://rest.payamak-panel.com` از سرور |

## ۵. تغییر ارائه‌دهنده در آینده

برای افزودن ارائه‌دهنده جدید (کاوه‌نگار، SMS.ir و …):

1. در `apps/api/src/modules/sms/provider.ts` یک شیء با اینترفیس `SmsProvider` بسازید
   (`sendPattern`, `sendSimple`, `ping`, `configured`).
2. آن را در `getProvider()` بر اساس `sms.provider` برگردانید.
3. هیچ تغییری در منطق احراز هویت، اعلان‌ها یا رابط کاربری لازم نیست.
