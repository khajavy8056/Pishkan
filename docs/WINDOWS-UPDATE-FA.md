# به‌روزرسانی نسخهٔ محلی ویندوز از GitHub

> قاعدهٔ طلایی: **هیچ به‌روزرسانی‌ای نباید دادهٔ آزمون را پاک کند و هیچ تغییر پایگاه داده‌ای
> نباید خارج از مهاجرت‌های رسمی انجام شود.** مسیر زیر همین را تضمین می‌کند.

---

## ۱. پیش از هر به‌روزرسانی

1. سرور را متوقف کنید (به‌صورت نرم):

   ```bat
   windows\Stop-Pishkan.cmd
   ```

2. پشتیبان بگیرید:

   ```bat
   node windows\lib\manager.mjs backup --root .
   ```

   خروجی باید شامل «پشتیبان ساخته شد» و تعداد مهاجرت/کاربران باشد. اگر خطا داد، **به‌روزرسانی
   را انجام ندهید** تا مشکل حل شود.

3. (اختیاری) از `.env.windows.local` و پوشهٔ `.data\uploads` یک کپی بگیرید.

---

## ۲. دریافت کد جدید

### الف) با Git (روش پیشنهادی)

```bat
git fetch origin
git status
git pull --ff-only origin main
```

اگر Git نصب نیست: نسخهٔ جدید را از صفحهٔ Releases در GitHub به‌صورت ZIP دریافت و روی
همان پوشه باز کنید (فایل‌های `.data` و `.env.windows.local` را **دست نزنید**).

> اگر تغییرات محلی روی کد دارید (`git status` فایل‌های تغییریافته نشان می‌دهد)، ابتدا آن‌ها را
> commit یا stash کنید؛ `git pull` با تغییرات محلی تداخل می‌کند.

### ب) بررسی تغییرات مهاجرت‌ها

```bat
dir apps\api\migrations
```

فایل‌های جدید (مثلاً `017_*.sql`) فقط با اجرای نصب/آپدیت اعمال می‌شوند؛ مهاجرت‌های قبلی
دوباره اجرا نمی‌شوند و داده‌های موجود حفظ می‌شوند.

---

## ۳. اعمال به‌روزرسانی

همان نصب‌کننده، نقش «تعمیر/به‌روزرسانی» را هم دارد:

```bat
windows\PishkanSetup.cmd
```

یا در حالت متنی:

```bat
windows\PishkanSetup.cmd /console
```

در این اجرا:

* فایل تنظیمات موجود **حفظ** می‌شود (کلید رمزنگاری، پورت و مسیرها تغییر نمی‌کنند)،
* `npm ci` فقط اگر بسته‌ها کم/ناقص باشند اجرا می‌شود،
* build دوباره ساخته می‌شود،
* مهاجرت‌های **جدید** روی همان پایگاه داده اعمال می‌شوند (هیچ جدولی حذف نمی‌شود)،
* اگر حساب مدیر وجود داشته باشد، دست‌نخورده می‌ماند،
* در پایان، آزمون نهایی (۱۷ بررسی) اجرا می‌شود.

اگر آزمون نهایی شکست بخورد، نصب‌کننده **موفق اعلام نمی‌کند** و گزارش در
`.data\install-error.json` نوشته می‌شود. در این حالت:

1. `git log --oneline -5` را ببینید (چه نسخه‌ای گرفته‌اید)،
2. با `git checkout <commit قبلی>` به نسخهٔ قبل برگردید،
3. `windows\PishkanSetup.cmd` را دوباره اجرا کنید،
4. اگر لازم شد، پایگاه داده را از پشتیبان بازگردانید:

   ```bat
   node windows\lib\manager.mjs restore --root . --file .data\backups\<backup>.sqlite
   ```

## ۴. پس از به‌روزرسانی

```bat
windows\Start-Pishkan.cmd
node windows\lib\verify.mjs --mode core --url http://127.0.0.1:3000 --env .env.windows.local
```

انتظار: `همهٔ بررسی‌ها موفق بود.`

برای اطمینان از سلامت گردش‌کارها (اختیاری، داده ساختگی می‌سازد):

```bat
node windows\lib\verify.mjs --mode workflow --url http://127.0.0.1:3000 --env .env.windows.local --admin-user admin --admin-pass "<رمز>"
```

---

## ۵. یادآوری‌ها

* میان‌برهای منوی شروع و دسکتاپ به فایل‌های `.cmd` داخل همین پوشه اشاره می‌کنند؛ پس از
  به‌روزرسانی نیازی به ساخت دوبارهٔ آن‌ها نیست.
* اگر مسیر پوشهٔ پروژه را تغییر دادید، میان‌برها را دوباره بسازید:
  `powershell -ExecutionPolicy Bypass -File windows\Create-Shortcuts.ps1`
* `node_modules` هنگام به‌روزرسانی بازسازی می‌شود؛ این کار زمان می‌برد ولی داده‌ها را
  تحت تأثیر قرار نمی‌دهد.
* هیچ‌گاه `.env.windows.local` را در Git قرار ندهید؛ کلید رمزنگاری محلی در آن است.
