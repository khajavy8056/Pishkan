# به‌روزرسانی نسخهٔ محلی ویندوز از GitHub

> قاعدهٔ طلایی: **هیچ به‌روزرسانی‌ای نباید دادهٔ آزمون را پاک کند و هیچ تغییر پایگاه داده‌ای
> نباید خارج از مهاجرت‌های رسمی انجام شود.** مسیر زیر همین را تضمین می‌کند.

---

## ۱. پیش از هر به‌روزرسانی

1. سرور را متوقف کنید (به‌صورت نرم):

   ```bat
   windows\Stop-Pishkan.cmd
   ```

2. پشتیبان بگیرید:

   ```bat
   node windows\lib\manager.mjs backup --root .
   ```

   خروجی باید شامل «پشتیبان ساخته شد» و تعداد مهاجرت/کاربران باشد. اگر خطا داد، **به‌روزرسانی
   را انجام ندهید** تا مشکل حل شود.

3. (اختیاری) از `.env.windows.local` و پوشهٔ `.data\uploads` یک کپی بگیرید.

---

## ۲. دریافت کد جدید

### الف) با Git (روش پیشنهادی)

```bat
git fetch origin
git status
git pull --ff-only origin main
```

اگر Git نصب نیست: نسخهٔ جدید را از صفحهٔ Releases در GitHub به‌صورت ZIP دریافت و روی
همان پوشه باز کنید (فایل‌های `.data` و `.env.windows.local` را **دست نزنید**).

> اگر تغییرات محلی روی کد دارید (`git status` فایل‌های تغییریافته نشان می‌دهد)، ابتدا آن‌ها را
> commit یا stash کنید؛ `git pull` با تغییرات محلی تداخل می‌کند.

### ب) بررسی تغییرات مهاجرت‌ها

```bat
dir apps\api\migrations
```

فایل‌های جدید (مثلاً `017_*.sql`) فقط با اجرای نصب/آپدیت اعمال می‌شوند؛ مهاجرت‌های قبلی
دوباره اجرا نمی‌شوند و داده‌های موجود حفظ می‌شوند.

---

## ۳. اعمال به‌روزرسانی

همان نصب‌کننده، نقش «تعمیر/به‌روزرسانی» را هم دارد:

```bat
windows\PishkanSetup.cmd
```

یا در حالت متنی:

```bat
windows\PishkanSetup.cmd /console
```

در این اجرا:

* فایل تنظیمات موجود **حفظ** می‌شود (کلید رمزنگاری، پورت و مسیرها تغییر نمی‌کنند)،
* در هر اجرا وابستگی‌ها با `npm install` برای درخت موجود (یا `npm ci` برای نصب تازه) و سپس `npm ls` بررسی می‌شوند؛ اگر ساخت خطای نبود ماژول/تعریف نوع بدهد، یک‌بار `node_modules` با `npm ci` بازسازی و ساخت تکرار می‌شود،
* build دوباره ساخته می‌شود،
* مهاجرت‌های **جدید** روی همان پایگاه داده اعمال می‌شوند (هیچ جدولی حذف نمی‌شود)،
* اگر حساب مدیر وجود داشته باشد، دست‌نخورده می‌ماند،
* در پایان، آزمون نهایی (۱۷ بررسی) اجرا می‌شود.

اگر آزمون نهایی شکست بخورد، نصب‌کننده **موفق اعلام نمی‌کند** و گزارش در
`.data\install-error.json` نوشته می‌شود. در این حالت:

1. `git log --oneline -5` را ببینید (چه نسخه‌ای گرفته‌اید)،
2. با `git checkout <commit قبلی>` به نسخهٔ قبل برگردید،
3. `windows\PishkanSetup.cmd` را دوباره اجرا کنید،
4. اگر لازم شد، پایگاه داده را از پشتیبان بازگردانید:

   ```bat
   node windows\lib\manager.mjs restore --root . --file .data\backups\<backup>.sqlite
   ```

## ۴. پس از به‌روزرسانی

```bat
windows\Start-Pishkan.cmd
node windows\lib\verify.mjs --mode core --url http://127.0.0.1:3000 --env .env.windows.local
```

انتظار: `همهٔ بررسی‌ها موفق بود.`

برای اطمینان از سلامت گردش‌کارها (اختیاری، داده ساختگی می‌سازد):

```bat
node windows\lib\verify.mjs --mode workflow --url http://127.0.0.1:3000 --env .env.windows.local --admin-user admin --admin-pass "<رمز>"
```

## ۵. یادآوری‌ها

* میان‌برهای منوی شروع و دسکتاپ به فایل‌های `.cmd` داخل همین پوشه اشاره می‌کنند؛ پس از
  به‌روزرسانی نیازی به ساخت دوبارهٔ آن‌ها نیست.
* اگر مسیر پوشهٔ پروژه را تغییر دادید، میان‌برها را دوباره بسازید:
  `powershell -ExecutionPolicy Bypass -File windows\Create-Shortcuts.ps1`
* `node_modules` هنگام به‌روزرسانی بازسازی می‌شود؛ این کار زمان می‌برد ولی داده‌ها را
  تحت تأثیر قرار نمی‌دهد.
* هیچ‌گاه `.env.windows.local` را در Git قرار ندهید؛ کلید رمزنگاری محلی در آن است.

## رفع صفحهٔ سفید مرورگر روی گوشی در شبکهٔ محلی

نسخهٔ شاخهٔ `arena/ffc5afe7-pishkan` اصلاح سیاست امنیتی وب را دارد: روی HTTP محلی، مرورگر دیگر فایل‌های صفحه را به HTTPS موجودنبودۀ سرور تغییر نمی‌دهد. برای دریافت اصلاح، کد **همین شاخه** را در محل نصب به‌روزرسانی کنید، ابتدا پشتیبان بگیرید، سپس نصب‌کننده را در حالت عادی (نه نصب تمیز) اجرا کنید تا API و وب دوباره ساخته و سرور راه‌اندازی شود. فقط تعویض فایل‌های منبع یا نصب APK جدید کافی نیست. سپس روی گوشی متصل به همان Wi-Fi، آدرس `http://IP-لپ‌تاپ:2981` را دوباره باز کنید؛ پورت را از مدیر سامانه بررسی کنید.

اگر تنظیم CSP سفارشی در تنظیمات امنیتی فعال است، به‌صورت خاص بررسی کنید که دستور `upgrade-insecure-requests` را برای سرور HTTP محلی اجباری نکرده باشد. HTTP محلی رمزنگاری ندارد: فقط در شبکهٔ مورد اعتماد استفاده شود؛ برای استفادهٔ اینترنتی، HTTPS معتبر لازم است.

## رفع خطای adm-zip

اگر هنگام ساخت `TS2307: Cannot find module 'adm-zip'` دیدید، شمارش زیاد بسته‌ها
نشانهٔ نصب کامل نیست. این اصلاح فعلاً در شاخهٔ `arena/ffc5afe7-pishkan` و PR #6 است،
نه لزوماً در `main` یا یک Release. از صفحهٔ همین شاخه در GitHub، **Code → Download ZIP**
را بگیرید. پس از توقف سرور و تهیهٔ پشتیبان پایگاه داده، فایل‌های کد نسخهٔ جدید را در
پوشهٔ نصب جایگزین کنید؛ `.data` و `.env.windows.local` و فایل‌های شخصی را جایگزین یا حذف نکنید.
سپس `windows\PishkanSetup.cmd` را از همان پوشه اجرا کنید و **نصب تمیز را انتخاب نکنید**.

اگر فعلاً نمی‌توانید نصاب جدید را دریافت کنید، در PowerShell در **ریشهٔ همان پوشهٔ
نصب** (جایی که `package.json` قرار دارد) بعد از توقف سرور و پشتیبان، اجرا کنید:

```powershell
cd 'C:\Pishkan'  # مسیر واقعی نصب خودتان را جایگزین کنید
npm install --include=dev --include=optional --ignore-scripts=false --no-audit --no-fund
```

اگر دستور موفق بود، نصاب موجود را دوباره در حالت عادی اجرا کنید. در صورت تکرار خطا
ممکن است فایل داخلی بسته آسیب دیده باشد؛ برای بازسازی فقط `node_modules` می‌توانید
پس از پشتیبان‌گیری و توقف سرور از `npm ci --include=dev --include=optional --ignore-scripts=false --no-audit --no-fund`
استفاده و سپس نصاب را اجرا کنید. `npm ci` کل `node_modules` را پاک و دوباره ایجاد می‌کند،
اما نباید `.data`، تنظیمات یا پشتیبان‌ها را حذف کرد. هر دو دستور ممکن است به اینترنت
`registry.npmjs.org` یا cache کامل نیاز داشته باشند؛ به خروجی خطا و
`.data\install-error.json` توجه کنید. این راه تعمیر و آزمون خودکار روی لینوکس سنجیده شده،
اجرای آن روی ویندوز واقعی در محیط توسعه تأیید نشده است.
