# تست اپ اندروید روی کامپیوتر ویندوز (شبیه‌ساز)

هدف: دیدن و بررسی اپ اندروید مشتریان روی همان کامپیوتری که سامانه روی آن اجرا می‌شود،
بدون گوشی واقعی.

> **کوتاه:** اپ فلاتر مستقیماً «روی ویندوز» اجرا نمی‌شود؛ یک **شبیه‌ساز اندروید** روی
> ویندوز اجرا می‌شود و اپ داخل آن نصب می‌شود. مسیر شما درست است، به شرط رعایت دو نکتهٔ
> پایین (آدرس `10.0.2.2` و باز بودن پورت برای شبکه).

---

## ۱. چرا «نسخهٔ ویندوز» اپ وجود ندارد

اپ موبایل (`apps/mobile`) فقط پوشهٔ `android` دارد. فلاتر برای ویندوز به پوشهٔ `windows/`
و به افزونه‌هایی نیاز دارد که روی دسکتاپ کار کنند؛ این افزونه‌ها در این پروژه
**اندروید-فقط** هستند:

| افزونه | کاربرد | روی ویندوز دسکتاپ |
|---|---|---|
| `workmanager` | بررسی پس‌زمینهٔ اعلان‌ها | پشتیبانی نمی‌شود |
| `flutter_local_notifications` | کانال‌ها و صدای اعلان | پشتیبانی نمی‌شود |
| `mobile_scanner` | اسکن QR | پشتیبانی نمی‌شود |
| `camera` / `image_cropper` | دوربین مدارک | پشتیبانی نمی‌شود |
| `local_auth` | اثر انگشت | پشتیبانی نمی‌شود |

ساختن نسخهٔ ویندوز یعنی جایگزین کردن این پنج مورد با stub — کاری بزرگ و بی‌فایده، چون
چیزی که می‌خواهید بسنجید (اعلان، دوربین، حس لمس) همان چیزهایی است که روی دسکتاپ
رفتار واقعی ندارند. **شبیه‌ساز اندروید همان تجربهٔ واقعی را می‌دهد.**

---

## ۲. پیش‌نیازها روی ویندوز

1. **Android Studio** → در `Settings > SDK Manager` این دو را نصب کنید:
   - Android SDK Platform (API 34 یا بالاتر)
   - **Android Emulator** و یک تصویر سیستم (Google APIs، x86_64)
2. در `Device Manager` یک شبیه‌ساز بسازید (Pixel 6 / API 34 خوب است).
3. **Flutter SDK** و `flutter doctor` بدون خطای قرمز.
4. در شبیه‌ساز، حالت توسعه را روشن کنید (شبیه‌سازهای Google APIs از قبل دارند).

---

## ۳. سامانه (بک‌اند) را روی ویندوز اجرا کنید

```powershell
cd apps\api
npm install
npm run migrate
npm run seed
npm run dev
```

باید ببینید:

```
[boot] Pishkan API ... listening on http://127.0.0.1:3000
```

### ⚠️ نکتهٔ حیاتی: روی ویندوز، سرور به‌طور پیش‌فرض فقط لوکال است

در `apps/api/src/lib/server-bind.ts` روی ویندوز آدرس گوش‌دادن این‌طور تعیین می‌شود:

```
HOST=0.0.0.0  +  LAN_ACCESS=true   →  0.0.0.0   (قابل دسترس از شبیه‌ساز/گوشی)
در غیر این صورت                    →  127.0.0.1 (فقط خودِ کامپیوتر)
```

یعنی اگر فقط `npm run dev` بزنید، شبیه‌ساز **به سرور نمی‌رسد**. باید متغیر محیطی را
اضافه کنید (در PowerShell، قبل از `npm run dev`):

```powershell
$env:HOST="0.0.0.0"; $env:LAN_ACCESS="true"; npm run dev
```

یا این دو خط را در `.env` کنار `apps/api` بگذارید:

```env
HOST=0.0.0.0
LAN_ACCESS=true
```

بعد از اجرا، همین را روی خود ویندوز امتحان کنید تا مطمئن شوید پورت باز است:

```powershell
curl http://localhost:3000/api/health
```

> فایروال ویندوز ممکن است یک بار اجازه بخواهد؛ برای پروفایل «Private» اجازه بدهید.

---

## ۴. اپ را روی شبیه‌ساز اجرا کنید

شبیه‌ساز را باز کنید، بعد:

```powershell
cd apps\mobile
flutter pub get
flutter run --dart-define=APP_ENV=local --dart-define=API_BASE_URL=http://10.0.2.2:3000
```

### ⚠️ نکتهٔ حیاتی دوم: `10.0.2.2` یعنی «خودِ کامپیوتر»

از دید شبیه‌ساز اندروید:

| آدرس | یعنی |
|---|---|
| `127.0.0.1` / `localhost` | خودِ شبیه‌ساز (نه ویندوز) |
| **`10.0.2.2`** | **همان کامپیوترِ میزبان (ویندوز)** |
| `192.168.x.x` | گوشی واقعی روی همان Wi‑Fi |

پس در شبیه‌ساز **باید** `10.0.2.2` باشد، نه `localhost`.

#### راه جایگزین: بدون `--dart-define`

اگر با APK منتشرشده کار می‌کنید (یا `API_BASE_URL` را ست نکردید)، اپ در اولین اجرا
صفحهٔ «آدرس سامانه» را نشان می‌دهد. همان‌جا تایپ کنید:

```
10.0.2.2:3000
```

اپ خودش `http://` را اضافه می‌کند (`normalizeBaseUrl` در `lib/core/env.dart`).

> **نصب APK روی شبیه‌ساز:** فایل `app-arm64-v8a-release.apk` را از صفحهٔ Release
> دانلود کنید و روی پنجرهٔ شبیه‌ساز بکشید و رها کنید — یا:
> `adb install -r app-arm64-v8a-release.apk`
> (برای شبیه‌سازهای x86_64، فایل `app-x86_64-release.apk` را نصب کنید.)

## ۵. با گوشی واقعی روی همان Wi‑Fi

1. `ipconfig` را بزنید و IPv4 کامپیوتر را بردارید (مثلاً `192.168.1.10`).
2. سرور را با `HOST=0.0.0.0` و `LAN_ACCESS=true` بالا بیاورید (بخش ۳).
3. در اپ، آدرس را `192.168.1.10:3000` بدهید.
4. اجازهٔ فایروال برای پورت ۳۰۰۰ در پروفایل Private.

---

## ۶. چه چیزهایی را در شبیه‌ساز بررسی کنید

بیشتر چیزها دقیقاً مثل گوشی کار می‌کنند؛ چند مورد استثنا دارد:

| قابلیت | در شبیه‌ساز |
|---|---|
| ورود، خدمات، تصاویر، حالت شب | ✅ کامل |
| حرکت‌ها و انیمیشن‌ها | ✅ کامل |
| دوربین / اسکن QR | ⚠️ دوربین مجازی؛ از منوی شبیه‌ساز تصویر تزریق کنید |
| اثر انگشت | ⚠️ در تنظیمات شبیه‌ساز یک اثر انگشت ثبت کنید |
| **اعلان‌ها و بررسی پس‌زمینه** | ⚠️ **کامل قابل سنجش نیست** — شبیه‌ساز Doze واقعی ندارد و WorkManager زمان‌بندی گوشی واقعی را شبیه‌سازی نمی‌کند. برای سنجش واقعی «اعلان وقتی اپ بسته است» باید روی گوشی اندروید تست شود. |

---

## ۷. اگر اپ به سرور وصل نشد (عیب‌یابی به‌ترتیب)

1. **سرور روی `0.0.0.0` است؟** در لاگ باید `listening on http://0.0.0.0:3000` باشد.
   اگر `127.0.0.1` دیدید، `LAN_ACCESS=true` ست نشده است.
2. **پورت باز است؟** از ویندوز: `curl http://localhost:3000/api/health`
3. **از داخل شبیه‌ساز؟** در شبیه‌ساز مرورگر را باز کنید و `http://10.0.2.2:3000/api/health`
   را بزنید. اگر اینجا باز شد ولی اپ نه، آدرس داخل اپ اشتباه است.
4. **`localhost` نوشته‌اید؟** داخل شبیه‌ساز غلط است؛ `10.0.2.2` بگذارید.
5. **فایروال؟** موقتاً شبکهٔ خصوصی را تست کنید یا یک قاعدهٔ ورودی برای پورت ۳۰۰۰ بسازید.
6. **HTTPS اجباری؟** در نسخهٔ لوکال `http` مجاز است (`usesCleartextTraffic="true"`),
   پس خطای گواهی نباید ببینید.
