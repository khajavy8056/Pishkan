# تست اپ اندروید روی کامپیوتر ویندوز (نصب لوکال با PishkanSetup)

هدف: با `windows\PishkanSetup.cmd` سامانه را روی ویندوز بالا بیاورید، هم پنل وب را
ببینید و هم اپ اندروید مشتریان را به همان سرور محلی وصل کنید — بدون گوشی واقعی.

> **مسیر شما درست است.** فقط دو جا باید یک تنظیم داشته باشید، وگرنه اپ به سرور نمی‌رسد.
> این دو را در بخش ۳ و ۴ با علامت ⚠️ مشخص کرده‌ام.

---

## ۱. نصب با نصب‌کننده ویندوز

روی `windows\PishkanSetup.cmd` دوبار کلیک کنید (یا اگر GUI باز نشد:
`PishkanSetup.cmd /console`).

نصب‌کننده به‌ترتیب این کارها را می‌کند: بررسی سیستم → پاک‌سازی نصب قبلی → ساخت `.env` →
**دسترسی شبکه محلی** → نصب وابستگی‌ها → ساخت API و وب → ساخت پایگاه داده (SQLite) →
ساخت حساب مدیر کل → راه‌اندازی سرویس‌ها → آزمون نهایی.

در پایان، آدرس‌ها را نشان می‌دهد:

```
آدرس همین رایانه: http://127.0.0.1:3000
ورود مدیر و کارکنان: http://127.0.0.1:3000/login-admin
```

پورت پیش‌فرض **۳۰۰۰** است؛ اگر اشغال باشد نصب‌کننده پورت آزاد بعدی را انتخاب می‌کند و
همان را در گزارش پایان چاپ می‌کند. **همیشه همان پورتی را که چاپ شده استفاده کنید.**

> API خودِ نسخهٔ build‌شدهٔ وب را هم سرو می‌کند (`apps/web/dist`)، پس **یک پورت** هم برای
> پنل وب و هم برای `/api` کافی است. نیازی به `npm run dev` جداگانه روی ۵۱۷۳ نیست.

---

## ۲. ⚠️ تیک «دسترسی موبایل در Wi‑Fi» را بزنید

در صفحهٔ تنظیمات نصب‌کننده، این گزینه هست:

> ☐ دسترسی موبایل در Wi‑Fi (اختیاری؛ فقط Private/LocalSubnet؛ نیازمند Administrator؛ پیش‌فرض خاموش)

**این تیک را بزنید.** دلیلش این است که در `apps/api/src/lib/server-bind.ts` روی ویندوز:

```
LAN_ACCESS=true  +  HOST=0.0.0.0   →   گوش‌دادن روی 0.0.0.0  (شبیه‌ساز/گوشی می‌رسند)
در غیر این صورت                     →   127.0.0.1           (فقط خودِ کامپیوتر)
```

یعنی بدون این تیک، **سرور از بیرونِ کامپیوتر دیده نمی‌شود** و اندروید هیچ‌وقت وصل نمی‌شود.
نصب‌کننده با فعال‌کردن این تیک، `HOST=0.0.0.0` و `LAN_ACCESS=true` را در `.env` می‌نویسد
و یک قاعدهٔ فایروال فقط برای پروفایل Private می‌سازد.

اگر ویندوز اجازهٔ فایروال نداد، نصب متوقف نمی‌شود؛ بعداً از **Pishkan Manager** دکمهٔ
«📱 باز کردن فایروال برای موبایل» را بزنید (یک تأیید Administrator).

### دیدن آدرس و QR موبایل

بعد از نصب، `windows\PishkanManager.cmd` را باز کنید و دکمهٔ **«دسترسی موبایل / QR»** را
بزنید. اگر کامپیوتر به Wi‑Fi/router وصل باشد، آدرس‌هایی مثل
`http://192.168.1.10:3000` و یک QR (که فقط همان URL را دارد، بدون هیچ رمزی) نشان داده
می‌شود.

> اگر آدرس موبایل خالی بود، یعنی کامپیوتر به شبکهٔ خصوصی (RFC1918) وصل نیست —
> Wi‑Fi یا کابل را وصل کنید و Manager را تازه‌سازی کنید.

## ۳. اپ اندروید را روی شبیه‌ساز اجرا کنید

شبیه‌ساز اندروید را باز کنید (Android Studio → Device Manager)، بعد:

```powershell
cd apps\mobile
flutter pub get
flutter run
```

چون `API_BASE_URL` را ست نکرده‌اید، اپ در اولین اجرا صفحهٔ **«آدرس سامانه»** را نشان
می‌دهد. اینجا **باید** بنویسید:

```
10.0.2.2:3000
```

### چرا `10.0.2.2` و نه `127.0.0.1`

مستند رسمی اندروید: `10.0.2.2` یک **آلیاس ویژه به loopback میزبان** است و
`127.0.0.1` داخل شبیه‌ساز یعنی خودِ شبیه‌ساز.

**اما یک استثنای مهم:** این آلیاس به «loopback میزبان» اشاره می‌کند. اگر سرور روی
`0.0.0.0` گوش بدهد، `10.0.2.2` هم کار می‌کند؛ **ولی اگر سرور فقط روی `127.0.0.1`
باشد، نتیجه بسته به نسخهٔ شبیه‌ساز نامطمئن است.** پس تیک بخش ۲ را نزنید و روی
«شاید کار کند» حساب نکنید — با `LAN_ACCESS=true` هر دو حالت قطعی است.

#### جایگزین مطمئن: آدرس LAN واقعی

اگر آدرس `192.168.x.x:3000` را از Manager دارید، **همان** را در اپ بدهید. این آدرس
برای شبیه‌ساز و گوشی واقعی یکسان کار می‌کند و هیچ آلیاسی لازم ندارد.

#### اسکن QR

در همان صفحهٔ آدرس، دکمهٔ **«اسکن QR آدرس سرور»** هست. QRی که Manager نشان می‌دهد را
اسکن کنید — آدرس خودکار پر می‌شود. (در شبیه‌ساز، دوربین مجازی است؛ از منوی شبیه‌ساز
تصویر تزریق کنید یا آدرس را دستی بزنید.)

#### نصب APK منتشرشده به‌جای `flutter run`

فایل `app-x86_64-release.apk` را از صفحهٔ Release دانلود و روی پنجرهٔ شبیه‌ساز رها کنید
(برای شبیه‌سازهای x86_64؛ برای ARM همان `arm64`). بعد از نصب، همان آدرس را دستی وارد کنید.

## ۴. پنل وب را ببینید

روی خود ویندوز: `http://127.0.0.1:3000` — همان پورت، همان سرور.

از **داخل شبیه‌ساز** (اگر می‌خواهید رفتار وب را در مرورگر اندروید ببینید):
`http://10.0.2.2:3000` یا `http://192.168.1.10:3000`.

از گوشی واقعی روی همان Wi‑Fi: `http://192.168.1.10:3000`.

---

## ۵. اگر اتصال برقرار نشد — عیب‌یابی به‌ترتیب

1. **لاگ سرور را بخوانید.** در Manager، لاگ زنده را باز کنید. باید ببینید:
   `listening on http://0.0.0.0:3000`.
   اگر `127.0.0.1` دیدید ← تیک بخش ۲ نخورده. دوباره نصب کنید یا `HOST=0.0.0.0` و
   `LAN_ACCESS=true` را در `.env` بگذارید و از Manager «راه‌اندازی دوباره» بزنید.
2. **از خود ویندوز:** `curl http://127.0.0.1:3000/api/health` باید پاسخ بدهد.
3. **از داخل شبیه‌ساز:** مرورگر شبیه‌ساز را باز کنید و
   `http://10.0.2.2:3000/api/health` را بزنید.
   - باز شد ← مشکل در آدرس داخل اپ است.
   - باز نشد ← سرور روی loopback یا فایروال مانع است (بخش ۲).
4. **`localhost` نوشته‌اید؟** داخل شبیه‌ساز غلط است. `10.0.2.2` یا IP واقعی.
5. **پورت اشتباه؟** پورتی را که نصب‌کننده چاپ کرده استفاده کنید (ممکن است ۳۰۰۱ باشد).
6. **فایروال:** پروفایل شبکهٔ ویندوز باید **Private** باشد. برای Public قاعده ساخته نمی‌شود.
7. **خطای گواهی/HTTPS ندارید؟** در نسخهٔ لوکال `http` مجاز است
   (`usesCleartextTraffic="true"`).

## ۶. در شبیه‌ساز چه چیزی را واقعاً می‌توانید بسنجید

| قابلیت | شبیه‌ساز |
|---|---|
| ورود، خدمات، تصاویر، آیکون‌ها، حالت شب | ✅ کامل |
| حرکت‌ها و انیمیشن‌ها | ✅ کامل |
| پنل وب و API | ✅ کامل |
| دوربین / اسکن QR | ⚠️ دوربین مجازی؛ تصویر تزریق کنید |
| اثر انگشت | ⚠️ اول در تنظیمات شبیه‌ساز ثبت کنید |
| **اعلان‌ها و بررسی پس‌زمینه** | ⚠️ **قابل سنجش نیست** — شبیه‌ساز Doze واقعی ندارد و WorkManager مثل گوشی زمان‌بندی نمی‌کند. برای سنجش واقعی «اعلان وقتی اپ بسته است» باید گوشی اندروید واقعی تست شود. |

## ۷. خلاصهٔ یک‌خطی

```
۱) PishkanSetup.cmd  →  تیک «دسترسی موبایل در Wi‑Fi» را بزن
۲) PishkanManager.cmd →  آدرس موبایل و QR را بردار
۳) در اپ، روی شبیه‌ساز: 10.0.2.2:3000   (یا همان آدرس 192.168.x.x)
۴) در ویندوز: http://127.0.0.1:3000
```
