# نصب و راه‌اندازی Pishkan روی ویندوز (نسخهٔ محلی آزمون)

> این نسخه برای **آزمون و استفادهٔ محلی** است: پایگاه دادهٔ SQLite جدا، فایل تنظیمات جدا،
> هیچ اتصالی به سامانهٔ اصلی و هیچ داده/کلید واقعی ندارد.
> همان کد بک‌اند، رابط کاربری، مدل‌ها، مجوزها و گردش‌کارها اجرا می‌شود؛ تنها تفاوت، فایل
> پیکربندی و لانچر ویندوزی است.

---

## ۱. پیش‌نیازها

| مورد | حداقل | توضیح |
| --- | --- | --- |
| ویندوز | ۱۰ نسخه ۲۰۰۴ (Build 19041) یا جدیدتر، ۶۴ بیتی | ویندوز ۱۱ هم پشتیبانی می‌شود |
| Node.js | 22.22.2 یا جدیدتر | نصب‌کننده می‌تواند خودش نصب کند |
| npm | همراه Node.js | نیازی به نصب جداگانه نیست |
| فضای دیسک | ۳ گیگابایت آزاد | `node_modules` حدود ۴۲۰ مگابایت و build حدود ۱ مگابایت |
| اینترنت | فقط هنگام نصب | برای دریافت وابستگی‌ها از `registry.npmjs.org` |

نیازی به PostgreSQL، Docker، Visual Studio Build Tools یا دسترسی Administrator نیست
(نصب در پوشهٔ کاربر انجام می‌شود). اگر Node.js نصب نباشد، نصب‌کننده ابتدا با `winget`
و در صورت نبود آن با نصب‌کنندهٔ رسمی MSI از `nodejs.org` (با بررسی SHA-256) آن را نصب می‌کند.

---

## ۲. نصب گرافیکی (روش پیشنهادی)

1. پوشهٔ پروژه را باز کنید و روی **`windows\PishkanSetup.cmd`** دوبار کلیک کنید.
2. پنجرهٔ «نصب Pishkan روی ویندوز» باز می‌شود (راست‌به‌چپ، با دکمهٔ **تغییر تم** برای حالت روشن/تیره).
3. مقادیر را تکمیل کنید:

   | فیلد | توضیح |
   | --- | --- |
   | مسیر نصب | همان پوشهٔ پروژه؛ پوشهٔ `.data` و فایل تنظیمات داخل آن ساخته می‌شود |
   | پورت برنامه | پیش‌فرض `3000`. اگر اشغال باشد، نصب‌کننده پورت آزاد بعدی را انتخاب و گزارش می‌کند |
   | نام و نام خانوادگی مدیر کل | در پروفایل و تاریخچهٔ عملیات نمایش داده می‌شود |
   | نام کاربری مدیر کل | حروف انگلیسی، رقم، نقطه، زیرخط، خط تیره (۳ تا ۶۰ کاراکتر) |
   | رمز عبور و تکرار آن | حداقل ۱۰ کاراکتر، ترکیب حرف و رقم (همان سیاست سرور) |

4. **«بررسی سیستم»** را بزنید: نسخهٔ ویندوز، معماری، Node.js، npm، فضای دیسک، دسترسی
   نوشتن، اینترنت و پورت بررسی می‌شود. هیچ مرحله‌ای بدون عبور از این بررسی شروع نمی‌شود.
5. **«شروع نصب»** را بزنید. مراحل با درصد پیشرفت نمایش داده می‌شوند:

   | # | مرحله | کاری که انجام می‌شود |
   | --- | --- | --- |
   | ۱ | بررسی سیستم | همان بند ۴ |
   | ۲ | تنظیمات محلی | ساخت `.env.windows.local` با کلید رمزنگاری تصادفی و پورت آزاد |
   | ۳ | دانلود وابستگی‌ها | `npm ci` (چون `package-lock.json` وجود دارد) با شمارش بسته‌های استخراج‌شده، حجم و **۳ تلاش مجدد** در قطعی شبکه |
   | ۴ | ساخت برنامه | `npm run build` برای API و رابط کاربری |
   | ۵ | پایگاه داده | ساخت فایل SQLite جدید + اجرای ۱۶ مهاجرت رسمی + دادهٔ کاتالوگ (۳ دسته، ۳۰ خدمت، ۶ نقش) |
   | ۶ | حساب مدیر کل | ساخت مدیر با همان تابع رسمی احراز هویت (هش bcrypt، نقش `super_admin`) |
   | ۷ | راه‌اندازی | اجرای سرور به‌صورت detached + انتظار برای پاسخ `/api/health` |
   | ۸ | آزمون نهایی | ۱۷ بررسی واقعی (پایگاه داده، مهاجرت‌ها، مدیر، نقش‌ها، فایل‌ها، API، SPA، استاتیک، دسترسی‌ها) |

6. در پایان، آدرس برنامه و نام کاربری مدیر نمایش داده می‌شود. با **«باز کردن Pishkan»**
   برنامه در مرورگر پیش‌فرض باز می‌شود.

> اگر هر مرحله شکست بخورد، نصب **ناموفق** اعلام می‌شود، هیچ بخشی «موفق» گزارش نمی‌شود و
> جزئیات در `.data\install-error.json` نوشته می‌شود (دستور، کد خروج، انتهای خروجی).

### نصب متنی (بدون پنجره)

```bat
windows\PishkanSetup.cmd /console
```

نسخهٔ متنی همان موتور را اجرا می‌کند و برای ویندوز Server Core یا نشست‌های بدون رابط گرافیکی
مناسب است.

## ۳. اجرا و مدیریت روزمره

| کار | روش |
| --- | --- |
| اجرا و باز کردن برنامه | دوبار کلیک روی `windows\Start-Pishkan.cmd` یا میان‌بر «اجرای Pishkan» |
| توقف امن | `windows\Stop-Pishkan.cmd` یا میان‌بر «توقف Pishkan» |
| مدیریت کامل | `windows\PishkanManager.cmd` |
| ساخت میان‌بر منوی شروع و دسکتاپ | `powershell -ExecutionPolicy Bypass -File windows\Create-Shortcuts.ps1` |

پنجرهٔ مدیر (Pishkan Manager) این‌ها را نشان می‌دهد و انجام می‌دهد:

* وضعیت واقعی هر سرویس با چراغ سبز/قرمز: **Backend**، **API**، **رابط کاربری**،
  **پایگاه داده**، **ذخیره‌سازی فایل** (فایل‌ها، اندازهٔ پایگاه داده، تعداد فایل‌های ذخیره‌شده)
* دکمه‌های **شروع / توقف / راه‌اندازی دوباره / باز کردن Pishkan / پوشه داده**
* **گزارش زندهٔ سرور** (به‌روزرسانی هر ۵ ثانیه، قابل خاموش‌کردن)
* **پشتیبان‌گیری** و **بازیابی** پایگاه دادهٔ آزمون
* اطلاعات نصب: پورت، فایل تنظیمات، مسیر داده، مسیر گزارش

### خط فرمان (بدون رابط گرافیکی)

```bat
node windows\lib\manager.mjs status  --root .
node windows\lib\manager.mjs start   --root .
node windows\lib\manager.mjs stop    --root .
node windows\lib\manager.mjs restart --root .
node windows\lib\manager.mjs logs    --root . --lines 80
node windows\lib\manager.mjs backup  --root .
node windows\lib\manager.mjs restore --root . --file .data\backups\<backup>.sqlite
node windows\lib\manager.mjs open    --root .
```

خاموش‌کردن **نرم** است: مدیر از طریق «کانال کنترل محلی» (`PISHKAN_CONTROL_PIPE`، یک
named pipe) فرمان `shutdown` می‌فرستد و سرور با همان مسیر SIGTERM بسته می‌شود
(توقف پذیرش درخواست، بستن پایگاه داده، خروج با کد ۰). اگر سرور پاسخ ندهد، پس از ۱۵ ثانیه
فرآیند با `taskkill` بسته می‌شود و همین موضوع در گزارش نوشته می‌شود.

```

│  ├─ uploads\                     ← مدارک و فایل‌های آپلودی
│  │  ├─ incoming\  private\{originals,optimized,previews}\  public\
```

## ۵. امنیت و جداسازی از محیط اصلی

* فایل تنظیمات مستقل (`.env.windows.local`) با `APP_ENCRYPTION_KEY` تصادفی ۶۴ کاراکتری؛
  هرگز در Git ذخیره نمی‌شود (`.gitignore`).
* پایگاه دادهٔ مستقل و پوشهٔ فایل مستقل: هیچ اشتراکی با محیط عملیاتی ندارد.
* **رمز عبور مدیر کل در هیچ فایلی ذخیره نمی‌شود**؛ فقط هش bcrypt در پایگاه داده است و
  رمز از طریق stdin به فرآیند ساخت مدیر داده می‌شود (نه در آرگومان خط فرمان، نه در متغیر محیطی).
* `HOST=127.0.0.1` است؛ سرور فقط از همان رایانه در دسترس است.
* `DB_DRIVER=sqlite` فقط با `NODE_ENV=development` مجاز است (قانون خود پروژه).
* داده‌های واقعی مشتریان را وارد نکنید؛ این محیط آزمون است.

## ۶. رفع اشکال

| نشانه | علت و راه‌حل |
| --- | --- |
| «Node.js پیدا نشد» | دکمهٔ «نصب Node.js» را بزنید یا از `nodejs.org` نسخهٔ ۲۲ نصب کنید و PowerShell را ببندید/باز کنید |
| خطای شبکه در مرحلهٔ وابستگی‌ها | اتصال/پروکسی را بررسی کنید؛ نصب‌کننده ۳ بار تلاش می‌کند و سپس با گزارش دقیق متوقف می‌شود |
| «پورت … اشغال است» | در صفحهٔ نصب پورت دیگری بدهید؛ نصب‌کننده هم پورت آزاد پیشنهادی می‌دهد |
| سرور بالا نمی‌آید | `.data\logs\pishkan-server-error.log` و سپس `PishkanManager.cmd` را ببینید |
| فراموشی رمز مدیر کل | `node apps\api\dist\cli\reset-password.js --username admin --generate --unlock` (با `PISHKAN_ENV_FILE=.env.windows.local`) |
| خطای «پایگاه داده در حال استفاده است» | یک سرور دیگر روی همان فایل اجراست؛ ابتدا `Stop-Pishkan.cmd` |
| «تلاش‌های ورود بیش از حد مجاز» (۴۲۹) | سه بار «آزمون گردش‌کار» پشت سر هم اجرا شده است. یک دقیقه صبر کنید یا `AUTH_LOGIN_RATE_LIMIT` را در `.env.windows.local` بالاتر ببرید (پیش‌فرض نصب محلی: ۶۰) |
| نصب می‌گوید «تنظیمات موجود حفظ شد» ولی پورت عوض شده | اگر سرورِ همین نصب در حال اجرا باشد، پورت حفظ می‌شود؛ اگر برنامهٔ دیگری پورت را گرفته باشد، نصب‌کننده پورت آزاد بعدی را انتخاب و در گزارش می‌نویسد |
| پیام «حساب مدیر کل ساخته نشد» | نصب کامل است ولی ورود ممکن نیست؛ با `node apps\api\dist\cli\create-admin.js --username admin --stdin` بسازید (رمز از stdin خوانده می‌شود) |
| سرور پس از خطای نصب در حال اجرا مانده | از نسخهٔ فعلی دیگر رخ نمی‌دهد: نصب‌کننده در مسیر خطا سروری را که خودش بالا آورده بود متوقف می‌کند و `stoppedServer` را در `.data\install-error.json` می‌نویسد |

## ۷. آزمون صحت نصب

```bat
node windows\lib\verify.mjs --mode core     --url http://127.0.0.1:3000 --env .env.windows.local
node windows\lib\verify.mjs --mode workflow --url http://127.0.0.1:3000 --env .env.windows.local --admin-user admin --admin-pass "<رمز>"
```

`--mode core` هفده بررسی واقعی (پایگاه داده، مهاجرت، نقش‌ها، مدیر، ذخیره‌سازی، API، SPA،
دسترسی‌ها) و `--mode workflow` یک گردش‌کار سرتاسری ۲۱ گامه با چهار نقش کارکنان (کارشناس،
اپراتور، حسابدار، مدیر)، مشتری و مدیر کل اجرا می‌کند؛ شامل چرخهٔ رد/اصلاح مدرک، تحویل
نتیجه، گفت‌وگوی کارشناس و مشتری، صندوق خودکارسازی و گزارش حسابرسی. هر دو بدون mock به
API و پایگاه دادهٔ واقعی وصل می‌شوند.

اگر `--env` و `--root` را ندهید، اسکریپت فایل تنظیمات را در پوشهٔ جاری/پوشهٔ نصب خودش
پیدا می‌کند. اگر نصب بدون حساب مدیر انجام شده باشد، `--allow-missing-admin` آن بررسی را
به «یادآوری» تبدیل می‌کند.
