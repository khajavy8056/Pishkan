# ایمیل در تک پیشخوان — آنچه ساخته شده و آنچه در فاز سرور انجام می‌شود

این سند دو بخش دارد و مرز آن‌ها صادقانه است: **بخش الف** (سیستم ایمیل سامانه) در
کد ساخته و با سرور SMTP واقعی تست شده است؛ **بخش ب** (ایمیل سازمانی با دامنهٔ
خودتان) نیز **زیرساخت نرم‌افزاری‌اش در کد آماده و تست شده** — CLI، قالب سرویس،
API و رابط مدیریت. تنها چیزی که باقی می‌ماند **اجرای واقعی روی VPS** است (بالا
آوردن سرویس، تنظیم DNS/PTR، و تست تحویل به Gmail) که به سرور و دامنهٔ واقعی نیاز
دارد و در فاز نصب انجام می‌شود.

---

## الف) سیستم ایمیل سامانه — ساخته‌شده و تست‌شده ✅

### ارسال (SMTP)
- ماژول `modules/email` با nodemailer؛ تنظیمات در **تنظیمات سامانه → ایمیل و اعلان‌ها**:
  هاست/پورت/TLS، کاربر و رمز SMTP، نام و نشانی فرستنده، سقف روزانه، مقصد آزمایشی.
- دکمه‌های **بررسی اتصال SMTP** و **ارسال ایمیل آزمایشی** در همان صفحه.
- هر ارسال در دفتر `email_logs` ثبت می‌شود (موفق/ناموفق/ردشده + دلیل)؛ کلید
  یکتا مانع ارسال تکراری یک رویداد می‌شود؛ متن ایمیل‌ها پیش‌فرض ذخیره نمی‌شود.
- بدون هاست SMTP، حالت «شبیه‌ساز توسعه» فعال است و صادقانه می‌گوید ارسال واقعی انجام نشده.
- با هر سرویس SMTP کار می‌کند: ایمیل سازمانی خودتان (بخش ب)، Gmail (با App Password)،
  یا سرویس‌های ایرانی/خارجی ارسال ایمیل.

### جریان‌های حساب کاربری
- **بازیابی رمز با لینک ایمیل** برای کارکنان و مشتریان: صفحهٔ «فراموشی رمز» →
  لینک یک‌بارمصرف ۳۰ دقیقه‌ای → تعیین رمز جدید → بسته‌شدن همهٔ نشست‌های قبلی →
  ایمیل تأیید تغییر. پاسخ درخواست برای حساب موجود/ناموجود یکسان است (افشای کاربر نمی‌کند).
- **تأیید ایمیل با کد ۶ رقمی یا لینک** از پروفایل مشتری و صفحهٔ حساب کارمند
  (`/staff/account`). تغییر نشانی، تأیید را باطل می‌کند تا دوباره اثبات شود.
- **خوش‌آمد کارمند تازه**: هنگام ساخت حساب دارای ایمیل، لینک «تعیین رمز شخصی»
  می‌رود — به‌جای ردوبدل کردن رمز اولیه به‌صورت شفاهی.

### اعلان‌ها و آلارم‌ها (کانال هفتم اعلان‌ها)
- ایمیل حالا کانال رسمی اعلان‌هاست (`CHANNELS`): تیکت جدید/پاسخ/حل‌شدن، تغییر
  وضعیت و مراحل پرونده، پرداخت‌ها، هشدارهای گارد و پایش برای مدیران.
- **تنظیمات هر شخص**: در پروفایل مشتری و حساب کارمند، «اعلان‌های ایمیلی من» —
  کلید اصلی + تفکیک تیکت/پرونده/پرداخت/امنیت/اعلان عمومی.
- **تنظیمات سامانه**: روشن/خاموش بودن هر دسته در تنظیمات ایمیل؛ گارد هم
  `guard.email_enabled` جدا دارد با همان سقف ساعتی پیامک.
- قالب‌ها فارسی، RTL و سازگار با Gmail/Outlook‌اند و برای هر کار متن مخصوص دارند.

### تست واقعی انجام‌شده
`apps/api/tests/email-system.test.ts` در برابر **سرور SMTP واقعی** (aiosmtpd)
اجرا می‌شود: دریافت واقعی ایمیل، استخراج لینک/کد از متن، تعیین رمز، ورود با رمز
جدید، ابطال نشست‌های قبلی، تک‌بارمصرف بودن توکن، انقضا، سقف روزانه، عدم ارسال
تکراری، و دروازه‌های ترجیحات کاربر — **۱۵/۱۵ موفق**.

## ب) ایمیل سازمانی با دامنهٔ خودتان — زیرساخت در کد آماده ✅، اجرا روی VPS

هدف شما: صندوق‌هایی مثل `admin@yourdomain.ir` و `staff1@yourdomain.ir` که خودتان
از پنل مدیریت بسازید، واردشان بشوید، و در **اپ Gmail اندروید** هم ارسال/دریافت
داشته باشید. **تمام زیرساخت نرم‌افزاری این کار الآن در کد ساخته و تست شده است**؛
فقط اجرای واقعی آن (بالا آوردن سرویس، تنظیم DNS، تست تحویل به Gmail) به VPS و
دامنهٔ واقعی نیاز دارد و در فاز نصب انجام می‌شود.

### آنچه همین حالا در کد آماده است
- **`scripts/mail/pishkan-mail`**: CLI مدیریت سرور ایمیل (docker-mailserver):
  `install --domain`، `add/passwd/enable/disable/del/list`، `dns`، `gmail`، `tls`.
- **`scripts/mail/docker-compose.mail.yml`**: قالب سرویس SMTP/IMAP + Rspamd +
  Fail2ban + TLS لتس‌انکریپت.
- **API صندوق‌ها** (`/api/mailboxes`): ساخت/تغییر رمز/تعلیق/حذف + وضعیت سرور +
  اطلاعات اتصال Gmail. فقط ادمین (settings.edit). رمزها هرگز در دیتابیس محصول
  ذخیره نمی‌شوند — فقط در خود Mail Server. **۱۲ تست موفق** با CLI شبیه‌سازی‌شده.
- **رابط مدیریت** در تنظیمات → ایمیل: کارت «صندوق‌های ایمیل سازمانی» (ساخت،
  فهرست، تعلیق/فعال‌سازی، تغییر رمز، حذف) + راهنمای اتصال Gmail. تا وقتی سرویس
  نصب نشده، صادقانه پیام «نصب نشده» و مرحلهٔ بعد را نشان می‌دهد.
- **پنل سرور (منوی ۱۴)** و **اکشن‌های workflow** (`mail-install`/`mail-status`).
- نصب‌کنندهٔ اصلی، CLI و قانون sudo محدود را نصب می‌کند تا API بتواند صندوق بسازد.

### آنچه در فاز نصب روی VPS انجام می‌شود (برنامهٔ اجرا)

### ۱. پیش‌نیازهای واقعی (بدون این‌ها ایمیل سازمانی سالم ممکن نیست)
| مورد | چرا |
| --- | --- |
| VPS با IP ثابت و **پورت ۲۵ باز** | بسیاری از ارائه‌دهنده‌ها پورت ۲۵ را پیش‌فرض می‌بندند؛ باید درخواست بازکردن بدهید (برای دریافت نامه ضروری است) |
| **PTR (Reverse DNS)** روی IP | باید به `mail.yourdomain.ir` اشاره کند؛ فقط ارائه‌دهندهٔ VPS می‌تواند تنظیم کند. بدون آن Gmail نامه‌ها را اسپم می‌کند |
| دامنه + دسترسی DNS (Cloudflare) | رکوردهای MX/SPF/DKIM/DMARC |
| RAM اضافه (~۱GB) | سرویس ایمیل + ضداسپم کنار سامانه |

### ۲. رکوردهای DNS که هنگام نصب ساخته می‌شوند
- `MX` → `mail.yourdomain.ir` (اولویت ۱۰)
- `A` برای `mail` → IP سرور (در Cloudflare **DNS only / خاکستری** — پورت ایمیل از پروکسی CF عبور نمی‌کند)
- `TXT` SPF: `v=spf1 mx ~all`
- `TXT` DKIM: کلید عمومی تولیدشده روی سرور
- `TXT` DMARC: `v=DMARC1; p=quarantine; rua=mailto:postmaster@…`
- PTR: از پنل ارائه‌دهندهٔ VPS

### ۳. سرویس ایمیل (انتخاب‌شده: docker-mailserver)
قالب آمادهٔ `docker-compose.mail.yml` از **docker-mailserver** استفاده می‌کند:
- SMTP (25/465/587) + IMAPS (993) + ضداسپم Rspamd + DKIM + Fail2ban + TLS
- ساخت صندوق با `pishkan-mail add` (یا از رابط مدیریت)؛ رمزها فقط روی سرور شما
- نصب با یک دستور: `pishkan-mail install --domain office.ir` (یا اکشن
  `mail-install` در workflow / منوی ۱۴ پنل). سپس `pishkan-mail dns` رکوردها را
  چاپ می‌کند و `pishkan-mail gmail` تنظیمات اتصال اپ Gmail را.

### ۴. اتصال اپ Gmail اندروید (ارسال و دریافت کامل)
در Gmail: Settings → Add account → **Other (IMAP)**:
- Incoming: `mail.yourdomain.ir`، پورت **993**، SSL/TLS، نام کاربری = نشانی کامل
- Outgoing: `mail.yourdomain.ir`، پورت **465** (SSL) یا **587** (STARTTLS)
- همان رمز صندوق. از همان لحظه ارسال/دریافت داخل اپ Gmail انجام می‌شود.

### ۵. مدیریت از پنل تک پیشخوان (ساخته شده ✅)
بخش «صندوق‌های ایمیل سازمانی» در تنظیمات → ایمیل آماده است: ساخت/تعلیق/حذف صندوق
با پسوند دامنهٔ ادمین اصلی، تعیین رمز، و نمایش وضعیت سرور + راهنمای Gmail. این
رابط به API و سپس به `pishkan-mail` روی سرور وصل است. تا وقتی Mail Server واقعاً
نصب نشده، رابط صادقانه وضعیت «نصب نشده» را نشان می‌دهد و ساخت صندوق پیام روشن
«سرویس نصب نشده» می‌دهد (نه خطای مبهم). منوی ۱۴ پنل ترمینالی هم همین کارها را دارد.

### ۶. هشدارهای صادقانهٔ تحویل‌پذیری
- IP تازه‌بدون‌سابقه ممکن است اوایل نزد Gmail/Outlook کم‌اعتبار باشد؛ گرم‌کردن
  تدریجی و SPF/DKIM/DMARC درست، اعتبار را می‌سازد.
- اگر ارائه‌دهنده پورت ۲۵ را باز نکند یا PTR ندهد، جایگزین: ارسال از طریق
  رله SMTP معتبر (مانند سرویس‌های ارسال ایمیل) + دریافت روی همان سرور با IMAP.
- وضعیت نهایی (رکوردها، تست ارسال به Gmail، تست IMAP) در گزارش نصب ثبت می‌شود.

## ترتیب اجرا
1. **الان (انجام شده):** سیستم ایمیل سامانه (الف) + زیرساخت ایمیل سازمانی (ب) در
   کد آماده و تست شده‌اند. روی سرورِ آینده فقط تنظیمات SMTP را وارد می‌کنید یا
   Mail Server را با یک دستور بالا می‌آورید و سامانه به خودش وصل می‌شود.
2. **فاز نصب:** VPS + دامنه + DNS → `pishkan-mail install --domain …` → ساخت
   صندوق‌ها (از رابط یا پنل) → اتصال Gmail → تست واقعی ارسال/دریافت → ثبت در
   گزارش نصب.

### تست‌های انجام‌شده برای بخش ب
- API صندوق‌ها با CLI شبیه‌سازی‌شده: **۱۲/۱۲ موفق** (ساخت، اعتبارسنجی فارسی،
  تکراری ۴۰۹، تعلیق/فعال‌سازی، تغییر رمز، حذف، پیام «نصب نشده» ۵۰۳، دسترسی ۴۰۳).
- syntax و منطق CLI (`pishkan-mail`) بررسی شده؛ اجرای واقعی docker و تحویل به
  Gmail روی VPS واقعی در فاز نصب تأیید می‌شود (در محیط توسعه docker نیست).
