# اصلاحات، آزمون‌ها و مرز انتشار — ۲۰۲۶-۱۰-۲۷

**این گزارش جایگزین نتیجه تاریخی ممیزی نیست؛ وضعیت کد پس از اصلاحات را ثبت می‌کند. کد قابل انتشار برای بازبینی است، نه تأیید بهره‌برداری بدون شرط با اطلاعات واقعی.**

## اصلاحات اجراشده

- ورود رمزی مشتری به صورت پیش‌فرض و بدون وابستگی به پیامک؛ نگهداری نام کاربری؛ تفکیک چالش پیامکی کارکنان و مشتری؛ مسیر اثبات مالکیت شماره با نشست احراز‌شده؛ هیچ شماره‌ای صرف ثبت حساب تأییدشده علامت نمی‌خورد.
- نشست معتبر پس از بازیابی رمز؛ `await` واقعی کنترل رمز هنگام حذف MFA؛ جلوگیری از دورزدن MFA با ورود پیامکی کارکنان؛ مصرف بلیت MFA قبل از عملیات ناهمگام و کنترل فعال‌بودن حساب. ورود رمزی اضطراری مدیر کل با تغییر روش کارکنان مسدود نمی‌شود.
- نام، نام خانوادگی، موبایل، کنترل checksum کد ملی و شهر مرجع برای ثبت درخواست الزامی است. کنترل قالب **احراز هویت رسمی نیست**. هدایت مشتری به تکمیل پروفایل در رابط و کنترل مستقل روی سرور.
- پوشش سراسری یا شهرهای منتخب در DB و ویرایشگر خدمت؛ فیلتر کاتالوگ و جست‌وجو و منع درخواست مستقیم شهر نامجاز؛ شهر مرجع قابل افزودن از مدیریت. فهرست اولیه ۱۲ شهر است، **مرجع کامل همه شهرهای ایران نیست**.
- سیاست فوریت هر خدمت، درصد مبلغ پایه، زمان و ظرفیت همزمان؛ quote سروری ریالی صحیح، ردیف مستقل فاکتور، snapshot ثابت و کنترل رقابت ظرفیت در تراکنش. مبلغ quote با فاکتور آزموده شده است.
- محدودیت پرونده، مدارک، فایل، گفت‌وگو و پیشنهاد اختصاصی برای کارمند مسئول؛ تفکیک حسابداری دفتر از حقوق شخصی. منع تغییر حساب مدیریتی توسط مدیر داخلی و حفاظت آخرین مدیر کل فعال. پاسخ یادداشت مشتری، رویدادهای داخلی را برنمی‌گرداند.
- صف واجد شرایط بدون افشای مشخصات مشتری و پذیرش اتمیک با بررسی ظرفیت، مهارت و سیاست شیفت؛ کنترل شیفت فعال با حضور باز و ساعت تهران به جای صرف وجود شیفت آن روز.
- جلوگیری از فاکتور مضاعف هنگام پذیرش پیشنهاد اختصاصی و تراکنش واحد برای پذیرش.
- قرارداد ثابت ماهانه یا درصدی تاریخ‌دار، منع هم‌پوشانی، ثبت حقوق به نسبت روزهای قرارداد، سهم هنگام تأیید دریافت وجه (بدون مالیات فاکتور)، snapshot قرارداد و برگشت همان سهم اولیه هنگام استرداد. گردش مستقل و تسویه دارای کلید جلوگیری از تکرار؛ پنل شخصی و مدیریت به API واقعی وصل است.
- اصلاح دوباره‌کسرشدن بازپرداخت در درآمد؛ جلوگیری از مبلغ بیش از مانده و مبلغ رزروشده پرداخت در انتظار؛ شماره‌گذاری SQL اتمیک؛ تراکنش محلی AsyncLocalStorage برای SQLite و PostgreSQL؛ جلوگیری از اعمال مضاعف دریافت/بازپرداخت با شرط وضعیت و کلید عملیات.
- آداپتور زرین‌پال v4: request، لینک StartPay، callback عمومی بدون کوکی، تطبیق authority ذخیره‌شده، مبلغ ریالی سمت سرور، verify، تکرارپذیری امن callback و منع تأیید دستی پرداخت واقعی آنلاین. تنظیم‌نبودن پذیرنده خطای روشن دارد؛ انتخاب زرین‌پال هیچ‌گاه لینک mock نمی‌دهد. آیدی‌پیِ پیاده‌نشده صریحاً رد می‌شود.
- اطلاعات اتصال پذیرنده و نام کاربری پیامک مانند سایر secrets رمزگذاری و در تنظیمات mask می‌شوند؛ مقدار قدیمی plaintext هنگام راه‌اندازی بدون حذف داده به رمزگذاری ارتقا می‌یابد. متن پیامک توسعه دیگر در log چاپ نمی‌شود و console SMS در production رد می‌شود.
- SQLite snapshot با API رسمی backup به جای کپی فایل زنده؛ DDL و ثبت checksum هر migration در یک تراکنش؛ CLI بدون sqlite3 از fallback خام استفاده نمی‌کند، خطای آرشیو را مخفی نمی‌کند و pg_restore با single transaction/exit-on-error اجرا می‌شود. اعتبارسنجی مسیر/نوع اعضای آرشیو، checksum الزامی و توقف موفق سرویس پیش از بازیابی.
- بازیابی از API فعال در production مسدود و به CLI آفلاین هدایت شده است. حذف پشتیبان نیازمند `confirmation: DELETE` است.
- مسیرهای `/api/v1/...` کنار مسیرهای قبلی حفظ شده‌اند. bearer session موجود برای کلاینت بومی قابل استفاده است؛ این به معنی ساخت APK نیست.
- رابط فارسی RTL با تم سبز نفتی/سرمه‌ای، فونت محلی، هدف لمسی موبایل، حالت کاهش حرکت، پروفایل استاندارد، quote، مدیریت شهر و فوریت، حقوق و صف پذیرش. صفحه اصلی از کاتالوگ واقعی استفاده می‌کند و پرونده یا کد پیگیری ساختگی نشان نمی‌دهد. کش آفلاین پاسخ‌های API حذف شده تا کاتالوگ شخصی بین حساب‌ها باقی نماند.

## آزمون‌های اجراشده

| بررسی | نتیجه |
|---|---|
| تست‌های API شامل اصلاحات جدید | ۵۹ آزمون |
| تست‌های React در jsdom | ۱۴ آزمون |
| آزمون مستقل پذیرش A01 تا A16 | هر ۱۶ مورد موفق پس از اصلاحات؛ در ممیزی قبل هر ۱۶ ناموفق بودند |

۹ تست جدید در `apps/api/tests/corrections.test.ts`: فوریت و رقابت ظرفیت، جغرافیا و حفظ snapshot، پذیرش همزمان، تأیید/بازپرداخت همزمان، حقوق/تسویه تکرارناپذیر و حریم خصوصی، قرارداد request/verify زرین‌پال با fetch جایگزین‌شده، برگشت سهم اولیه، بازیابی snapshot در DB مجزای آزمایشی، API نسخه‌دار و تأیید مالکیت شماره.

آزمون restore فقط round-trip پایگاه داده SQLite در مقصد ایزوله است؛ **بازیابی کامل Ubuntu/PostgreSQL/مدارک توسط CLI اجرا نشده است**. تست زرین‌پال قرارداد HTTP را با پاسخ‌های کنترل‌شده بررسی کرده؛ **پرداخت بانکی واقعی نیست**. UI در jsdom آزموده شده؛ مرورگر واقعی و دستگاه Windows/Android آزموده نشده‌اند.

```bash
npm ci
npm run typecheck
npm test
npm exec --workspace apps/api -- vitest run --config audit.config.ts
npm run build
npm audit
shellcheck -S warning scripts/install.sh scripts/pishkan scripts/lib/common.sh
```

تغییر fixtureها: درخواست مثبت اکنون پروفایل کامل دارد؛ A04 عمداً شهر را موقتاً خالی و سپس بازیابی می‌کند. fixture کارکنان فقط در DB آزمایشی verified می‌شود؛ ایجاد کارمند در محصول چنین کاری نمی‌کند. تست تأیید دستی آنلاین قبلی که رفتار ناامن را تأیید می‌کرد اکنون انتظار 403 دارد؛ اثبات پرداخت موفق از callback سروری در تست جدید انجام می‌شود.

## موارد باقی‌مانده؛ مانع ادعای تکمیل تمام سند

1. **ملی‌پیامک:** registry الگوی جداگانه همه رویدادها، outbox پایدار، retry/backoff/dedup کامل و worker عملیاتی هنوز ساخته نشده‌اند. بدون تأیید صریح و شماره مقصد، هیچ پیامک واقعی از این محیط ارسال نشده است.
2. **حسابداری کامل:** گزارش خالص مالیات/تفکیک نقدینگی از سود در همه حالت‌های تعهدی، اصلاحیه‌های غیرقابل‌تغییر، تقسیم سهم چند همکار برای یک پرونده، تغییر/خاتمه قرارداد باز و reconciliation زمان‌بندی‌شده درگاه هنوز کامل نیستند. گزارش‌های فعلی را گزارش مالی قانونی یا سود حسابرسی‌شده معرفی نکنید. حقوق ثابت فعلاً ماه عملیاتی میلادی دارد؛ ماه جلالی حقوق پیاده نشده است.
3. **همزمانی PostgreSQL:** اتصال تراکنش‌ها اصلاح شده ولی آزمون contention با PostgreSQL واقعی اجرا نشده؛ تست‌های رقابت فعلی SQLite هستند.
4. **عملیات:** نصب/ارتقا/rollback و restore کامل شامل مدارک روی Ubuntu واقعی، انتقال پشتیبان خارج سرور و اجرای زمان‌بندی خودکار همه تنظیمات backup هنوز نیازمند پیاده‌سازی/آزمون عملیاتی هستند. تغییر تنظیم cron به‌تنهایی worker ایجاد نمی‌کند.
5. **نیروی کار:** شیفت شبِ عبوری از نیمه‌شب، ظرفیت زمانی، جانشین، هشدار تأخیر و escalation کامل نشده‌اند. صف فعلی حداکثر ۲۰۰ پرونده نامنتسب را برای واجدشرایط‌بودن بررسی می‌کند. پالایش کامل جست‌وجوی پرونده پیش از pagination باقی است.
6. **دامنه امنیت و معماری:** ممیزی تکمیلی همه endpointهای مشتریان/نقش‌های سفارشی و تغییر همزمان آخرین مدیر لازم است. tenancy مستقل و جداسازی چند دفتر در schema هنوز اجرا نشده است.
7. **انتشار محصول:** دامنه/HTTPS و ارائه‌دهندگان واقعی تنظیم نشده‌اند؛ آزمون مرورگر و دستگاه واقعی انجام نشده؛ APK نهایی ساخته نشده و باید پس از دامنه و API تولید ساخته شود.

**سبزشدن ۱۶ آزمون پذیرش و ۷۳ تست عادی به معنی تکمیل همه ۲۶ بخش سند یا مجوز استفاده از داده‌های حساس واقعی نیست.**

## مهاجرت و بازبینی

`006_profile_geography_urgency.sql` و `007_payroll.sql` افزایشی‌اند. هیچ مشتری، فاکتور، تراکنش یا تنظیم موجود حذف نمی‌شود؛ پروفایل‌های قدیمی برای درخواست جدید باید تکمیل شوند. شهر و سیاست فعلی به پرونده‌های قبلی اعمال مجدد نمی‌شوند. قبل از هر ارتقای تولید، پشتیبان قابل بازیابی و تست staging لازم است.

این نسخه روی شاخه `arena/82749fce-pishkan` است، نه `main`. اسکریپت نصب پیش‌فرض main را استفاده می‌کند؛ برای ارزیابی این کد، شاخه را صریحاً انتخاب کنید. استقرار تولید به اتکای پیش‌نمایش موقت توصیه نمی‌شود.

## مجوز GitHub Actions

GitHub App فعلی اجازه ساخت یا تغییر `.github/workflows/ci.yml` ندارد و push شامل آن را رد کرد. برای انتشار سورس بدون تغییر سطح دسترسی، workflow فعال از commit کنار گذاشته و نسخه نمونه همان تنظیمات در `docs/CI-WORKFLOW.example.yml` منتشر شده است. تست‌های گزارش‌شده محلی اجرا شده‌اند؛ CI فعال یا موفق GitHub Actions ادعا نشده است. فایل فعال در workspace باقی است. پس از تأیید دوباره اتصال GitHub در Arena با مجوز workflows، می‌توان آن را منتشر و اجرا کرد.
