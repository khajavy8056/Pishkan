# دسترسی عامل به سرور — راهنمای کامل

این سند دقیقاً همان چیزی است که خواستید: یک دستور برای **اتصال اولیه**، دسترسی
**کامل در زمان نصب**، و یک دستور برای **قطع دسترسی**. بعد از قطع، عامل فقط با
**درخواست + تأیید شما در پنل** و برای **مدت دلخواه شما** وصل می‌شود.

---

## ۱) اتصال اولیه (قبل از نصب) — یک دستور

روی سرور تازه (VPS) با.root وارد شوید و این را اجرا کنید:

```bash
curl -fsSL https://raw.githubusercontent.com/khajavy8056/Pishkan/main/scripts/pishkan-agent-bootstrap | sudo bash
```

این دستور به‌صورت خودکار:
- کاربر `pishkan-deploy` (دسترسی کامل برای نصب) و کاربر محدود `pishkan-agent` (فقط-خواندنی) را می‌سازد.
- دو کلید SSH می‌سازد و ابزار تأیید را نصب می‌کند.
- یک بلوک «GitHub Secrets» چاپ می‌کند: `VPS_HOST`، `VPS_PORT`، `VPS_USER`، `VPS_HOST_KEY`، `VPS_SSH_KEY`، `AGENT_SSH_KEY`.

**شما چه کار کنید:** هر مقدار را در گیت‌هاب کپی کنید:
`Settings → Secrets and variables → Actions → New repository secret`
- نام secret = همان برچسب (مثلاً `VPS_HOST`)، مقدار = چیزی که چاپ شده.
- برای `VPS_SSH_KEY` و `AGENT_SSH_KEY` **کلید خصوصی کامل** (از خط BEGIN تا END) را کپی کنید.
- ⚠️ این کلیدها را **هرگز در چت نفرستید**؛ فقط در GitHub Secrets.
- پس از کپی، در ترمینال `clear` بزنید و ترمینال را ببندید.

سپس به عامل بگویید: «وصل شو و نصب کن». عامل از طریق workflow با `action=install`
وصل می‌شود و نصب را انجام می‌دهد.

> اگر کلیدها را گم کردید، دوباره چاپ می‌شوند: `sudo pishkan-agent-bootstrap keys`

---

## ۲) در زمان نصب — دسترسی کامل، بدون محدودیت زمانی

تا وقتی نصب کامل نشده، عامل با همان `VPS_SSH_KEY` **دسترسی کامل** دارد و هیچ
محدودیت زمانی یا تأیید per-session وجود ندارد. هر وقت خودتان خواستید می‌توانید
دسترسی را ببندید (بخش ۴). بعد از نصب هم **تا وقتی سکرت فعال است و رمز عوض نشده**،
عامل با همان سکرت به‌طور کامل وصل می‌شود — بدون درخواست و بدون زمان‌سنج.

---

## ۳) بعد از نصب و بعد از ابطال سکرت — دسترسی با درخواست

وقتی سکرت اصلی را باطل کردید، عامل دیگر دسترسی مستقیم ندارد. از آن پس هر بار
برای انجام کاری باید **درخواست** بدهد و **شما تأیید کنید**:

1. عامل یک درخواست در شاخهٔ `pishkan-agent-requests` مخزن منتشر می‌کند:
   شناسه، دلیل، و **مدت پیشنهادی** (مثلاً «۲۰ دقیقه لازم دارم چون می‌خواهم
   تنظیمات را تغییر دهم و تست بگیرم»).
2. شما با PuTTY وارد سرور می‌شوید → پنل مدیریت → **گزینهٔ ۱۳ «درخواست‌های دسترسی عامل»**.
   فهرست درخواست‌ها با **دلیل** و **مدت درخواستی** نمایش داده می‌شود.
3. شناسه را وارد می‌کنید و برای تأیید:
   - `y` → همان مدتی که عامل خواسته (پیش‌فرض ۱۵ دقیقه اگر چیزی نخواسته باشد).
   - `y 20` → بیست دقیقه.
   - `y 120` → دو ساعت.
   - هر عدد دیگری تا سقف ۱۴۴۰ دقیقه (۲۴ ساعت).
4. تأیید، کلید محدود عامل را با **انقضای خودکار OpenSSH** (`expiry-time`) فعال
   می‌کند. عامل در این بازه به‌صورت **فقط-خواندنی** (status/doctor/لاگ) وصل می‌شود.
5. پایان زمان = قطع خودکار. برای کار بعدی، درخواست و تأیید تازه لازم است.

**قطع فوری یک درخواست:** در همان منو `x` را بزنید و شناسه را وارد کنید، یا:
```bash
sudo pishkan-agent-requests revoke <شناسه>
```

**وضعیت پنجره‌های فعال:**
```bash
sudo pishkan-agent-requests status
```

> امنیت: تصمیم تأیید فقط روی خود سرور ذخیره می‌شود؛ گیت‌هاب هرگز آن را نمی‌بیند
> و عامل هیچ راهی برای تأیید درخواست خودش ندارد. کلید `AGENT_SSH_KEY` حتی اگر در
> گیت‌هاب بماند، **بدون تأیید شما روی سرور غیرفعال است** (فایل authorized_keys خالی
> است و فقط در پنجرهٔ تأییدشده پر می‌شود). کاربر عامل هیچ shell ندارد و فقط یک
> دستور تشخیصی مشخص را از طریق sudo اجرا می‌کند.

---

## ۴) قطع دسترسی کامل — یک دستور

هر وقت خواستید دسترسی کامل عامل را ببندید (رمز/کلید را باطل کنید):

```bash
sudo pishkan-agent-bootstrap revoke
```

این دستور:
- کلید کاربر `pishkan-deploy` را خالی و حساب را قفل می‌کند → دسترسی کامل قطع.
- کلید عامل و همهٔ تأییدهای فعال را پاک می‌کند.
- مسیر درخواست (بخش ۳) همچنان کار می‌کند: تأیید بعدی شما در پنل، کلید محدود را
  برای همان مدت فعال می‌کند.

**بستن همه‌چیز (حتی مسیر درخواست):** علاوه بر دستور بالا، secretهای
`VPS_SSH_KEY` و `AGENT_SSH_KEY` را از گیت‌هاب حذف کنید. در این حالت عامل هیچ راه
اتصالی ندارد تا وقتی دوباره `setup` را اجرا کنید.

**فعال‌سازی دوبارهٔ دسترسی کامل:**
```bash
sudo pishkan-agent-bootstrap setup
```
(کلیدهای موجود حفظ می‌شوند؛ اگر لازم باشد کلید تازه می‌سازد و بلوک secrets را
دوباره چاپ می‌کند.)

---

## ۵) خلاصهٔ دستورها

| کار | دستور |
| --- | --- |
| اتصال اولیه + چاپ secrets | `curl -fsSL …/pishkan-agent-bootstrap \| sudo bash` |
| چاپ دوبارهٔ secrets | `sudo pishkan-agent-bootstrap keys` |
| وضعیت دسترسی | `sudo pishkan-agent-bootstrap status` |
| قطع دسترسی کامل | `sudo pishkan-agent-bootstrap revoke` |
| فهرست درخواست‌ها | `sudo pishkan-agent-requests list` |
| تأیید با زمان درخواستی | `sudo pishkan-agent-requests approve <id>` |
| تأیید با زمان دلخواه | `sudo pishkan-agent-requests approve <id> 20` |
| قطع یک درخواست | `sudo pishkan-agent-requests revoke <id>` |
| پاک‌سازی منقضی‌ها | `sudo pishkan-agent-requests prune` (هر دقیقه خودکار) |

---

## ۶) صداقت دربارهٔ تست

- منطق تأیید/پنجره/انقضای کلید: **۲۳ تست خودکار موفق** (`agent_access_test.py`).
- نشست تشخیصی فقط-خواندنی + رد بدون تأیید + مسیر کلید عامل: **۱۰ تست موفق** (`agent-session.e2e.sh`).
- ساخت واقعی کاربر/کلید روی سرور (bootstrap setup) نیاز به root دارد و در فاز
  نصب واقعی روی VPS شما اجرا و تأیید می‌شود؛ در محیط توسعه فقط منطق و syntax
  بررسی شده است.
