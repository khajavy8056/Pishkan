# اعلان لحظه‌ای اندروید (Firebase Cloud Messaging)

هدف: اعلانِ «مرحلهٔ پرونده عوض شد» و «خدمت شما آماده است» وقتی اپ **بسته** است هم
برسد و در **نوار اعلان گوشی** بنشیند — مثل بقیهٔ برنامه‌ها.

این سند سه چیز را روشن می‌کند: چه چیزی الان کار می‌کند، برای فعال‌شدن ارسال لحظه‌ای
چه باید بکنید، و کجا ممکن است به مشکل بخورید (بدون پرده‌پوشی).

> **خلاصه در یک خط:** بدون یک پروژهٔ Firebase از خودِ شما، اعلانِ «اپ بسته» کار
> نمی‌کند و اپ به بررسی دوره‌ای برمی‌گردد (کار می‌کند، ولی می‌تواند دیر برسد).
> این یک نقص نیست؛ محدودیت ذاتی روش است و در بخش ۵ دقیقاً گفته شده.

---

## ۰. وضعیت فعلی این نسخه

| بخش | وضعیت |
|---|---|
| سرور: ثبت توکن گوشی، ارسال FCM، گزارش تحویل | ✅ پیاده‌سازی و تست شده (۲۲ تست) |
| اپ: دریافت پیام، ساخت اعلان گرافیکی، مسیر لمس | ✅ کامپایل و بسته‌بندی شده؛ **روی گوشی واقعی تست نشده** |
| پروژهٔ Firebase | ✅ شناسه‌ها در اپ پر شده (`pishkhan-72e28`) |
| ساخت APK در GitHub Actions | ✅ موفق — تگ `android-v1.20.9` |
| کلید سرور (service account) | ⚠️ باید در پنل مدیریت وارد شود (در مخزن نیست) |
| بررسی دوره‌ای (جایگزین همیشگی) | ✅ کار می‌کند، بدون هیچ تنظیمی |

### APK آمادهٔ نصب

گردش‌کار `.github/workflows/android.yml` با تگ `android-v*` اجرا می‌شود. آخرین
ساخت موفق:

```
https://github.com/khajavy8056/Pishkan/releases/tag/android-v1.20.9
```

سه APK جدا برای معماری‌های مختلف ساخته می‌شود. برای تقریباً همهٔ گوشی‌های
امروزی **`app-arm64-v8a-release.apk`** را بردارید؛ `armeabi-v7a` برای گوشی‌های
قدیمی‌تر و `x86_64` فقط برای شبیه‌ساز است. فایل `app-release.aab` برای آپلود در
Google Play است و روی گوشی نصب نمی‌شود.

این APK با **کلید دیباگ** امضا شده، چون رازهای امضا در تنظیمات مخزن نیستند.
برای تست داخلی اشکالی ندارد؛ برای انتشار عمومی باید
`ANDROID_KEYSTORE_BASE64` و `ANDROID_KEYSTORE_PASSWORD` و `ANDROID_KEY_ALIAS`
اضافه شوند.

اپ شناسه‌های Firebase را از `res/values/firebase.xml` می‌خواند. اگر روزی آن‌ها
خالی باشند، اپ اصلاً FCM را راه نمی‌اندازد و کرش نمی‌کند — همین طراحی است تا
نسخهٔ بدون Firebase هم نصب شود.

## ۱. اعلانی که مشتری می‌بیند

اعلان‌ها data-only هستند: یعنی گوشی خودش ظاهر اعلان را می‌سازد، نه سرور. نتیجه:

- **آیکون** اختصاصی (مونوکروم تا در اندروید ۱۳+ درست دیده شود)
- **کانال صدا**ی متفاوت برای مرحلهٔ پرونده، پاسخ کارشناس، اطلاعیهٔ دفتر و پیام
- **نوار پیشرفت واقعی** روی اعلان: «مرحلهٔ ۳ از ۵ — ٪۶۰»، با نام مرحلهٔ فعلی
- **متن کامل** با BigTextStyle وقتی باز شود
- **جایگزینی نسخهٔ قبل:** دو اعلان از یک پرونده، دو تای در نوار نمی‌سازند؛
  جدیدتر جای قبلی را می‌گیرد (`collapse_key`). یک اعلان کهنه با «مرحلهٔ ۱» کنار
  اعلان «مرحلهٔ ۴» نمی‌ماند و مشتری را گیج نمی‌کند.
- **لمس اعلان** → مستقیم به همان صفحه: پرونده، پیام‌ها، یا فهرست اعلان‌ها

برای یک پرونده، اعلانِ مرحله تا **سه روز** بعد از باز شدن اپ هم در کش می‌ماند تا
اگر گوشی در حالت خواب بود، دیرتر تحویل داده شود.

## ۲. راه‌اندازی Firebase (یک‌بار برای همیشه)

این کار را **یک نفر** با دسترسی به کنسول Firebase انجام می‌دهد. سه چیز لازم است:
یک فایل JSON سمت سرور، و چهار مقدار داخل اپ.

> **وضعیت فعلی پروژه:** پروژهٔ `pishkhan-72e28` ساخته شده و چهار مقدار اپ در
> `firebase.xml` داخل مخزن پر شده است. یعنی تنها کاری که **باقی مانده** این است:
>
> 1. کنسول Firebase → ⚙️ **Project settings** → تب **Service accounts**
> 2. دکمهٔ **Generate new private key** → یک فایل `.json` دانلود می‌شود
> 3. پنل مدیریت پیشخوان → **پیامک و اعلان‌ها** → کارت اعلان‌ها → همان فایل را
>    بارگذاری کنید
>
> قدم ۳ را **حتماً** از داخل پنل انجام دهید، نه با گذاشتن فایل در مخزن. سرور
> محتوای فایل را رمزنگاری‌شده در پایگاه داده نگه می‌دارد و هیچ‌وقت به گوشی یا
> مرورگر فرستاده نمی‌شود. از این به بعد ارسال لحظه‌ای کار می‌کند.
>
> بخش‌های ۲.۱ تا ۲.۳ پایین‌تر فقط برای وقتی است که بخواهید پروژهٔ Firebase
> دیگری بسازید یا از صفر بازسازی کنید.

### ۲.۱ ساخت پروژه

1. <https://console.firebase.google.com> → **Add project**
2. داخل پروژه: **Add app → Android**
3. نام بستهٔ اپ **(package name)** را دقیقاً همین بگذارید:
   `ir.pishkan.app`
   > اگر تغییرش دهید، پیام‌ها هرگز نمی‌رسند و هیچ خطایی هم نمی‌بینید. این
   > رایج‌ترین اشتباه است.
4. `google-services.json` را دانلود کنید — **آن را در پروژه commit نکنید.**

### ۲.۲ چهار مقدار برای اپ

از `google-services.json`:

| مقدار در `firebase.xml` / `-P…` | از کجای JSON |
|---|---|
| `firebase_project_id` | `project_info.project_id` |
| `firebase_application_id` | `client[0].client_info.mobilesdk_app_id` |
| `firebase_api_key` | `client[0].api_key[0].current_key` |
| `firebase_sender_id` | `project_info.project_number` |

این‌ها **کلید عمومی** هستند و بودن‌شان در APK اشکالی ندارد.

دو راه برای گذاشتن‌شان:

**الف) فایل `apps/mobile/android/app/src/main/res/values/firebase.xml`** (ساده‌تر)

> ✅ برای پروژهٔ فعلی این کار انجام شده است. مقادیر `pishkhan-72e28` در همین
> فایل داخل مخزن هستند و APK ساخته‌شده با همین‌ها بسته‌بندی شده — لازم نیست
> دوباره وارد کنید. بقیهٔ این بخش فقط برای پروژهٔ Firebase دیگر یا بازسازی است.

```xml
<resources>
    <string name="firebase_project_id" translatable="false">my-project-12345</string>
    <string name="firebase_application_id" translatable="false">1:123456789:android:abcdef123456</string>
    <string name="firebase_api_key" translatable="false">AIzaSy...</string>
    <string name="firebase_sender_id" translatable="false">123456789</string>
</resources>
```

**ب) زمان build، بدون تغییر فایل:**

```bash
flutter build apk --release \
  -PfirebaseProjectId=my-project-12345 \
  -PfirebaseAppId=1:123456789:android:abcdef123456 \
  -PfirebaseApiKey=AIzaSy... \
  -PfirebaseSenderId=123456789
```

> چرا `google-services.json` و پلاگین `com.google.gms.google-services` استفاده
> نشده؟ چون آن پلاگین وقتی JSON نباشد **build را می‌شکند** — یعنی CI و هر
> همکاری که پروژهٔ Firebase شما را ندارد نمی‌تواند اپ را بسازد. و چون هر
> deployment پروژهٔ خودش را دارد. با روش بالا، build همیشه موفق است و فقط اپ
> بدون اعلان لحظه‌ای می‌ماند تا مقادیر پر شوند.

### ۲.۳ کلید سمت سرور

1. Firebase Console → **⚙ Project settings → Service accounts**
2. **Generate new private key** → یک فایل `.json` دانلود می‌شود
3. پنل مدیر کل → **پیامک و اعلان‌ها** → «کلید حساب سرویس Firebase» → محتوای
   کامل فایل را بچسبانید
4. کلید «ارسال اعلان لحظه‌ای به گوشی مشتریان» را **روشن** کنید

این کلید **رمز شده** در پایگاه داده ذخیره می‌شود، هرگز به گوشی یا مرورگر فرستاده
نمی‌شود و در گزارش‌ها نمایش داده نمی‌شود. اگر لو رفت، از کنسول Firebase همان
کلید را Revoke کنید و کلید تازه بسازید.

### ۲.۴ آزمون

مسیر: پنل مدیر کل → **تنظیمات → پیامک و اعلان‌ها** → کارت **«اعلان لحظه‌ای گوشی
(Firebase)»**. همان‌جا وضعیت کلید، نام پروژه، تعداد گوشی‌های ثبت‌شده و آخرین
تحویل‌ها را می‌بینید، و دکمهٔ «ارسال آزمایشی» و «به‌روزرسانی وضعیت» هست.

اگر:

- «ارسال شد» دیدید اما گوشی چیزی نشان نداد → بخش ۴
- «ارسال نشد: …» دیدید → پیام دقیقاً می‌گوید کدام قطعه کم است

از گوشی هم: **پروفایل → اعلان‌ها → «ارسال آزمایشی از سرور»**. این یکی مهم‌تر است،
چون از سمت سرور می‌آید و اپِ بسته را هم بیدار می‌کند.

## ۳. تفاوت «بررسی دوره‌ای» و «ارسال لحظه‌ای»

اپ دو مسیر دارد و **هر دو با هم** کار می‌کنند:

| | بررسی دوره‌ای | ارسال لحظه‌ای (FCM) |
|---|---|---|
| نیاز به تنظیم | ندارد | پروژهٔ Firebase |
| اپ باز | فوری | فوری |
| اپ بسته | فقط اگر اندروید اجازه دهد؛ ممکن است ساعت‌ها دیر شود | ✅ می‌رسد |
| اینترنت ایران | کار می‌کند (سرور خودتان) | بستگی به دسترسی گوشی به سرویس‌های گوگل |

بررسی دوره‌ای **حذف نشده** و نباید حذف شود: پوشش همهٔ گوشی‌هایی است که FCM
ندارند یا پروژهٔ Firebase ندارند. اعلان لحظه‌ای روی آن اضافه می‌شود، جایگزینش
نمی‌شود.

## ۴. اگر اعلان نرسید — به ترتیب بررسی کنید

1. **آیا گوشی روی سرویس‌های گوگل است؟** گوشی‌های بدون Google Play Services
   (بعضی گوشی‌های چینی، بعضی ویوو/اوپو) هیچ‌وقت FCM نمی‌گیرند. مسیر حل: بررسی
   دوره‌ای، یا نصب سرویس‌های گوگل.
2. **آیا اجازهٔ اعلان داده شده؟** پروفایل → اعلان‌ها. اگر نوشته «اجازهٔ اعلان داده
   نشده»، با دکمهٔ همان صفحه بدهید.
3. **آیا بهینه‌سازی باتری اپ را خواب می‌کند؟** پروفایل → اعلان‌ها → «اجازهٔ اجرا در
   پس‌زمینه» → «بدون محدودیت». این رایج‌ترین علتِ «اول کار می‌کرد بعد قطع شد».
4. **آیا گوشی ثبت شده؟** پروفایل → اعلان‌ها → دکمهٔ «ارسال آزمایشی از سرور».
   اگر گفت «هیچ دستگاهی ثبت نشده»، اپ توکن نگرفته: یعنی `firebase.xml` خالی است.
5. **پنل مدیر کل → اعلان‌ها → گزارش تحویل.** ستون‌های `errorCode`:
   - `UNREGISTERED` / `NOT_FOUND` — توکن مرده است؛ دستگاه خودکار حذف شده و با
     ورود بعدی مشتری دوباره ثبت می‌شود. طبیعی است.
   - `INVALID_ARGUMENT` — نام بستهٔ اپ با پروژهٔ Firebase نمی‌خواند (بخش ۲.۱).
   - `THIRD_PARTY_AUTH_ERROR` / ۴۰۳ — کلید حساب سرویس غلط یا منقضی است.
   - `QUOTA_EXCEEDED` / ۴۲۹ — سهمیهٔ روزانهٔ پروژه پر شده.
   - `SENDER_ID_MISMATCH` — `firebase_sender_id` با پروژهٔ کلید سرور یکی نیست.

هیچ‌کدام از این‌ها باعث خطای اپ نمی‌شود: ارسال لحظه‌ای وقتی شکست بخورد، بی‌صدا
رد می‌شود و بررسی دوره‌ای کار خودش را می‌کند.

## ۵. واقعیت ایران — صریح و بدون تعارف

**راه‌اندازی** Firebase از IP ایران کار نمی‌کند (خطای «This service is not
available from Iran»). یعنی ساختن پروژه و گرفتن کلیدها **باید** از یک IP دیگر
(VPN، سرور خارج، یا کسی که خارج است) انجام شود. این یک‌بار است.

**تحویل** پیام به گوشی، مسیر دیگری است: از سرویس‌های گوگل روی خود گوشی عبور
می‌کند و به همین دلیل معمولاً بدون VPN هم می‌رسد. گزارش‌ها این را تأیید می‌کنند
(مثلاً Batch صریحاً می‌گوید کاربران ایرانی‌اش اعلان می‌گیرند؛ برای OneSignal
موارد ناقص هم گزارش شده). ولی این **تضمین نیست**: اگر گوشی به سرویس‌های گوگل
دسترسی نداشته باشد، FCM نمی‌رسد. هیچ روشی نمی‌تواند این را دور بزند، چون در
اندروید، تحویلِ اعلان در حالت بسته فقط از این مسیر ممکن است.

**سمت سرور:** سرور باید به `fcm.googleapis.com` دسترسی داشته باشد. روی سرور
گوگل/ابر خارجی مشکلی نیست. روی هاست داخل ایران ممکن است وصل نشود — در آن حالت
از همان پنل، نشانی واسط را در «نشانی سرویس ارسال» بگذارید، یا اپ را روی بررسی
دوره‌ای نگه دارید.

**جایگزین‌های ایرانی** (پوشه، نجوا و مانند این‌ها) هر کدام اپ و SDK خودشان را
می‌خواهند و سرویس اعلانِ گوگل را دور نمی‌زنند؛ برای «اپ بسته» راه تمیزی
نیستند. راه‌حل واقعی اگر FCM نگرفت: همان بررسی دوره‌ای، که در کد هست.

## ۷. محدودیت‌هایی که باید بدانید

- **اپ روی گوشی واقعی تست نشده.** همه‌چیز روی کد بررسی شده و CI آن را build
  می‌کند، ولی «اولین اعلان روی گوشی» باید توسط شما دیده شود. اگر نیامد، بخش ۴.
- **بدون پروژهٔ Firebase، اعلانِ اپ بسته تضمینی نیست.** این تنها محدودیت واقعی
  است و بالا صادقانه نوشته شده.
- **پوشه/نجوا/وان‌سیگنال** جانشین نیستند: هر سه در نهایت از سرویس اعلان گوگل
  عبور می‌کنند.
- **گوشی‌های بدون Google Play Services** هیچ‌وقت FCM نمی‌گیرند. برایشان بررسی
  دوره‌ای تنها راه است.
